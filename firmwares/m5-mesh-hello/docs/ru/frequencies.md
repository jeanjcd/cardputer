# Регионы и частоты

Всё о радиорегионах, частотах, мощности передачи и рабочем цикле (duty cycle) в M5-Mesh-Hello v0.1.0. Все значения взяты из [`src/mesh/region.h`](../../src/mesh/region.h) и [`src/mesh/region.cpp`](../../src/mesh/region.cpp). Нативный тест `test/test_docs_regions` при каждом запуске CI сверяет таблицу регионов из **английской версии** этого документа с кодом (см. [Как поддерживается точность таблицы](#как-поддерживается-точность-таблицы)).

> **Юридическое примечание.** Всегда используйте регион страны, в которой вы физически находитесь. Вы сами отвечаете за соблюдение местных правил радиосвязи (частота, мощность, рабочий цикл, усиление антенны). Этот документ — техническая информация, а не юридическая консультация.

## Что такое регион Meshtastic

LoRa-радио в каждый момент слушает ровно одну частоту. Чтобы два узла Meshtastic могли общаться, они должны использовать одну и ту же частоту и одинаковые параметры модема. Meshtastic определяет **регион** для каждой регуляторной зоны. Регион — это частотный диапазон (начало и конец), ограничение рабочего цикла, лимит мощности и шаг каналов. Узел берёт регион, имя канала (здесь `LongFast`) и ширину полосы и по фиксированной формуле вычисляет из них фактическую центральную частоту. Поэтому все узлы одного региона с каналом по умолчанию оказываются на одной частоте без какой-либо координации.

M5-Mesh-Hello всегда использует пресет **LongFast** (ширина полосы 250 kHz, spreading factor 11, coding rate 4/5, sync word `0x2B`, преамбула 16 символов, явный заголовок, CRC включён) на основном канале по умолчанию с именем `LongFast`. Регион — единственная настройка радио, которую вы выбираете. Меняется он на экране **Config** (`Região`; Enter перебирает список). По умолчанию — **ANZ**.

## Как вычисляется частота

Код в точности повторяет `RadioInterface::applyModemConfig()` из Meshtastic, включая арифметику с плавающей точкой одинарной точности ([`regionFreqMHz`](../../src/mesh/region.cpp)):

```
hash        = djb2("LongFast")                       // 130429955
numChannels = floor((freqEnd - freqStart) / (spacing + bw/1000))
slot        = hash % numChannels
freq        = freqStart + bw/2000 + slot * bw/1000   // MHz; bw in kHz (250)
```

- `djb2` — классический хеш строк: начинаем с `h = 5381`, затем для каждого байта `h = h * 33 + byte` как беззнаковое 32-битное значение. Для `"LongFast"` получается **130429955**.
- `bw/2000` — половина ширины полосы в MHz (0.125 MHz), поэтому центр канала находится на половину ширины полосы выше начала его слота.
- Если бы `numChannels` был равен 0 (диапазон уже одного канала), код вернул бы `freqStart + bw/2000`. Ни один поддерживаемый регион под этот случай не попадает.

### Пример: ANZ

| Шаг | Значение |
|---|---|
| Диапазон | 915.0 – 928.0 MHz, шаг 0 |
| `numChannels` | floor(13.0 / (0 + 0.25)) = **52** |
| `slot` | 130429955 mod 52 = **19** |
| `freq` | 915.0 + 0.125 + 19 × 0.25 = **919.875 MHz** |

Тот же расчёт для других регионов:

| Регион | numChannels | slot | LongFast (MHz) |
|---|---|---|---|
| BR_902 | 22 | 7 | 903.875 |
| US | 104 | 19 | 906.875 |
| EU_868 | 1 | 0 | 869.525 |
| SG_923 | 32 | 3 | 917.875 |

### Хеш канала

Каждый кадр несёт в заголовке однобайтовый хеш канала, чтобы приёмник мог выбрать нужный ключ. Это XOR всех байтов имени канала, объединённый операцией XOR со всеми байтами ключа. Для `"LongFast"` с ключом по умолчанию он равен **`0x08`**. См. [protocol.md](protocol.md#шифрование-канала-aes-128-ctr).

## Мощность передачи

На экране Config задаётся мощность от 2 до 22 dBm (`Potência`, по умолчанию 22). Радио использует **эффективную мощность** ([`effectiveTxPower`](../../src/mesh/region.cpp)):

```
limit     = region power limit, or 17 dBm if the region's limit is 0 ("unknown", as in Meshtastic)
effective = min(user setting, limit, 22)     and at least 2 dBm
```

То есть `limit` — лимит мощности региона или 17 dBm, если лимит региона равен 0 («неизвестен», как в Meshtastic); эффективная мощность — минимум из вашей настройки, `limit` и 22, но не менее 2 dBm.

22 dBm — максимум SX1262. Если эффективная мощность ниже вашей настройки, экран Config показывает обе, например `22 dBm (efetiva 14)` («эффективная 14») в UA_868 или PH_868 либо `22 dBm (efetiva 20)` в RU и SG_923. Лимит мощности применяется заново при каждой смене региона.

Усиление антенны не учитывается. Если местные правила ограничивают ЭИИМ/ЭИМ (EIRP/ERP), а вы используете антенну с высоким усилением, снизьте мощность самостоятельно.

## Рабочий цикл и бюджет эфирного времени

Некоторые регионы ограничивают долю времени, в течение которой устройство может передавать: EU_868 и TH допускают 10 %, UA_868 — 1 %. В этих регионах прошивка ведёт скользящий часовой учёт эфирного времени ([`AirtimeBudget`](../../src/mesh/region.h)) и задерживает кадры, если следующий превысил бы бюджет.

- **Бюджет** = duty % от часа: 10 % → **360 с в час**, 1 % → **36 с в час**.
- **Учёт**: 61 минутная корзина. Кадр, отправленный в минуту *M*, учитывается до минуты *M + 60* включительно, то есть **не менее 3600 с** (до 3660 с). Ошибка всегда в безопасную сторону.
- **Перед каждой передачей** прошивка вычисляет время кадра в эфире (с округлением вверх до целых миллисекунд) и проверяет `used + airtime ≤ budget`. Если проверка не проходит, кадр и всё, что стоит в очереди за ним, **ждут**. Ничего не отбрасывается. Строка состояния показывает красным `duty limit`, а экран Config — `Ar 1h: Xs de Ys (duty Z%)` («эфир за последний час: X с из Y с»).
- В регионах с рабочим циклом 100 % бюджета нет, и строка в Config не показывается.

### Время в эфире

Прошивка использует формулу Semtech SX126x ([`loraAirtimeUs`](../../src/mesh/region.cpp)) с параметрами LongFast: SF11, BW 250 kHz, CR 4/5, преамбула 16, явный заголовок, CRC включён, оптимизация для низкой скорости передачи выключена.

```
Tsym          = 2^SF / BW                              = 2048 / 250 kHz = 8.192 ms
preamble      = (16 + 4.25) × Tsym                     = 165.888 ms
payloadSymbols = 8 + ceil((8·L − 4·SF + 28 + 16) / (4·SF)) × CR   // L = whole frame length in bytes, CR = 5
               = 8 + ceil(8·L / 44) × 5
airtime       = preamble + payloadSymbols × Tsym
```

(`L` — полная длина кадра в байтах; `CR` = 5.)

Таким образом, каждый кадр стоит фиксированные **≈ 231 мс** (L = 0) плюс 5 символов (41 мс) на каждые 5.5 байта, что в среднем составляет **≈ 7.4 мс на байт**:

| Длина кадра L (заголовок + полезная нагрузка) | Время в эфире |
|---|---|
| 0 Б (теоретический минимум) | 231 мс |
| 22 Б (короткий публичный текст, например «привет») | 395 мс |
| 88 Б (наш NodeInfo с именами по умолчанию) | 887 мс |
| 128 Б | 1.21 с |
| 200 Б | 1.75 с |
| 255 Б (максимальный кадр) | 2.16 с |

Типичный кадр занимает около **1 с**. В EU_868 360 с в час — это примерно 400 кадров размером с NodeInfo в час, намного больше, чем эта прошивка отправляет при обычном использовании. В UA_868 (36 с в час) помещается около 40 таких кадров в час.

## Экспериментальные регионы

M5Stack Cap LoRa-1262 рассчитан на **868–923 MHz**. Сама микросхема SX1262 перестраивается в диапазоне **150–960 MHz**, поэтому радио можно настроить на частоты чуть за пределами спецификации Cap. ВЧ-коммутатор, фильтрация и согласование Cap рассчитаны на номинальный диапазон. За его пределами ожидайте меньшей мощности передачи и худшей чувствительности. Насколько хуже — не измерялось.

Прошивка включает регионы с частотой LongFast в [860, 868) MHz (IN, NZ_865, NP_865, KZ_863) или (923, 925] MHz (JP, TW, TH) и помечает их:

- В Config регион отображается с `(exp)`, например `IN 865.875 (exp)`.
- При выборе такого региона появляется уведомление `Fora da faixa do Cap (exp)` («вне диапазона Cap (экспериментальный)»).
- Пока он выбран, Config показывает `! Fora de 868-923 MHz do Cap (exp)` («вне диапазона Cap 868–923 MHz»).

Используйте экспериментальный регион, только если это правильный регион для вашей страны, и ожидайте меньшей дальности.

**Япония (JP).** Японские правила для диапазона 920 MHz (ARIB STD-T108) могут требовать контроля несущей (LBT) и ограничений времени передачи; эта прошивка не реализует LBT и не проверялась на соответствие — перед передачей в Японии самостоятельно проверьте требования 電波法/技適.

## Бразилия

В Бразилии актуальны два региона, и они **не** слышат друг друга:

| Регион | LongFast | Статус |
|---|---|---|
| **ANZ** | 919.875 MHz | Его сегодня использует бразильское сообщество Meshtastic (например, [meshbrasil.com](https://meshbrasil.com)). **Значение по умолчанию в этой прошивке.** |
| **BR_902** | 903.875 MHz | Официальный регион Meshtastic для Бразилии (902–907.5 MHz). |

Правила Anatel (бразильского регулятора связи) для оборудования с ограниченным излучением (без лицензии) разрешают устройства с расширением спектра, такие как LoRa, в полосах **902–907.5 MHz и 915–928 MHz** внутри диапазона 902–928 MHz. Участок 907.5–915 MHz в это безлицензионное выделение не входит. Обе частоты, указанные выше, попадают в разрешённые участки. **Сверьтесь с действующими правилами Anatel**, прежде чем на это полагаться.

Если в ANZ вы никого не слышите, спросите местных пользователей, какой регион они используют, или попробуйте BR_902.

## Антенны по диапазонам

Антенна настраивается на определённый диапазон частот. Вдали от него КСВ (VSWR) растёт, и часть мощности отражается, а не излучается.

| Частота вашего региона | Лучшая антенна |
|---|---|
| 863–870 MHz (EU_868, RU, UA_868, PH_868, IN, NZ_865, NP_865, KZ_863) | Антенна на 868 MHz |
| 902–928 MHz (ANZ, BR_902, US, KR, MY_919, SG_923, PH_915, JP, TW, TH) | Антенна на 915 MHz |

Антенна из комплекта Cap настроена на 868 MHz. В регионах 902–928 MHz она всё равно работает, с ожидаемыми потерями около **0.5–2 dB**: 919.875 MHz примерно на 6 % выше её частоты настройки, а 903.875 MHz — примерно на 4 % выше. При КСВ 2:1 отражается около 11 % мощности (≈ 0.5 dB). При 3:1 потери ≈ 1.25 dB. Это стоит примерно 5–20 % дальности. Если покупаете антенну для региона 902–928 MHz, выбирайте настроенную на 915 MHz, а не «широкополосную». С антенной на 868 MHz регион BR_902 (903.875 MHz) чуть ближе к её частоте настройки, чем ANZ. Другие советы по дальности — в [hardware.md](hardware.md#антенна-и-дальность).

**Никогда не передавайте без подключённой антенны.** Прошивка передаёт NodeInfo сразу после запуска.

## Как поддерживается точность таблицы

В английской версии этого документа, [`docs/en/frequencies.md`](../en/frequencies.md), таблица регионов находится между HTML-комментариями `<!-- regions:begin -->` и `<!-- regions:end -->`. Нативный тест [`test/test_docs_regions`](../../test/test_docs_regions/test_main.cpp) читает тот файл, разбирает каждую строку таблицы и сравнивает её с `regionAt(i)` в том же порядке: имя, границы диапазона, частоту LongFast, вычисленную `regionFreqMHz`, лимит мощности, рабочий цикл и признак экспериментального региона. Тест выполняется при каждом `pio test -e native`, а значит, и в CI при каждом push и pull request. Если вы меняете `region.cpp`, обновите английскую таблицу в том же коммите (порядок столбцов важен для теста), а затем переводы. Переводы тест не проверяет.
