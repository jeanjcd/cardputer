# Руководство пользователя

Это руководство описывает M5-Mesh-Hello v0.1.0 на M5Stack **Cardputer-Adv** с модулем **Cap LoRa-1262**. В нём разобраны все экраны, клавиши, настройки и сообщения о состоянии.

Надписи на экране — на португальском языке. Руководство приводит их в точности так, как они отображаются, а в скобках даёт перевод на русский. В шрифте экрана нет некоторых букв с диакритикой, поэтому часть надписей на устройстве выглядит без диакритических знаков (см. [Ограничения дисплея](#ограничения-дисплея)).

## Перед началом работы

1. **Прикрутите антенну к Cap до включения.** Прошивка передаёт объявление NodeInfo меньше чем через секунду после запуска. Передача без антенны может повредить радиомодуль.
2. Установите прошивку через M5Launcher (см. [быстрый старт в README](../../README.ru.md#быстрый-старт) и [hardware.md](hardware.md#установка-через-m5launcher)).
3. Узнайте, какой регион используют пользователи Meshtastic рядом с вами. В Бразилии сообщество использует **ANZ** (значение по умолчанию). См. [frequencies.md](frequencies.md).

## Первый запуск

- При самом первом запуске устройство генерирует пару ключей X25519 с помощью аппаратного генератора случайных чисел и сохраняет её во флеш-памяти (NVS). После этого пара ключей **никогда не меняется**. Узлы Meshtastic запоминают первый открытый ключ, который они услышали от каждого узла («побеждает первый ключ»), поэтому новый ключ лишил бы их возможности отправлять вам личные сообщения.
- Ваш **ID узла** (`!xxxxxxxx`) берётся из заводского MAC-адреса чипа и тоже постоянен.
- Имена по умолчанию — **4stro-031** (длинное) и **4S31** (короткое). Их можно изменить на экране Config.
- Устройство запускается в регионе, сохранённом в прошлый раз (ANZ при новой установке), рассылает свой NodeInfo с просьбой к соседям прислать свои и затем слушает эфир.
- **Автоприветствие ВЫКЛЮЧЕНО** после каждого запуска.

## Структура экрана

Дисплей 240 × 135 показывает 40 столбцов текста (надписи выглядят так, как их рисует шрифт, например `auto-saudaçao`):

```
+----------------------------------------+
|ANZ 919.875 | AUTO:OFF | rx 42 | -97dBm |  <- строка состояния (или жёлтое уведомление)
| Nós*  | Conversa |  Canal  |  Config   |  <- вкладки (* = есть непрочитанное)
|BASE Base Stati TBEAM          -97  2m* |
|JOAO Joao Movel HELTEC_V3     -112 15s +|  <- один узел на строку
|a3f1 !9c2ea3f1  -                -   -  |
|                                        |
|Enter:conversa A:auto-saudaçao Tab:tela |  <- подсказка по клавишам / ввод текста
+----------------------------------------+
```

### Строка состояния

`<регион> <частота> | AUTO:ON или AUTO:OFF | rx <принято кадров> | <RSSI последнего кадра>`

- **Регион и частота** в MHz, например `ANZ 919.875`. Если радио не работает, вместо них здесь показывается `SEM CAP LoRa` или `RADIO ERRO` (см. [Устранение неполадок](#устранение-неполадок-все-состояния-и-сообщения)).
- **`AUTO:ON` / `AUTO:OFF`**: состояние автоприветствия.
- **`rx N`**: число кадров LoRa, принятых с момента запуска. Учитывается каждый кадр, который декодировал радиомодуль, включая те, которые прошивка не может прочитать (другие каналы, чужие личные сообщения). Если число растёт, радио что-то слышит.
- **RSSI** последнего принятого кадра, например `-97dBm`. До прихода первого кадра показывается `-dBm`, а `duty limit` — пока бюджет эфирного времени региона задерживает передачи.
- Если строка не помещается в 40 столбцов, пробелы вокруг `|` убираются.
- Строка становится **красной**, если Cap отсутствует, радио дало сбой или действует ограничение рабочего цикла.

**Уведомления** (toasts) — короткие сообщения, которые на 2.5 секунды заменяют строку состояния на жёлтом фоне, например `Config salva` («настройки сохранены»).

### Вкладки

`Nós` (узлы), `Conversa` (чат), `Canal` (канал), `Config`. Активная вкладка подсвечена. `Nós` превращается в `Nós*`, если у какого-либо узла есть непрочитанные личные сообщения, а `Canal` — в `Canal*`, если в публичном канале есть непрочитанные сообщения.

## Клавиши

| Клавиша | Где | Действие |
|---|---|---|
| `Tab` | везде | Следующий экран: Nós → Conversa → Canal → Config → Nós |
| `;` | Nós, Config | Переместить выделение вверх (на клавише `;` нарисована стрелка вверх) |
| `.` | Nós, Config | Переместить выделение вниз (на клавише `.` нарисована стрелка вниз) |
| `Enter` | Nós | Открыть переписку с выбранным узлом |
| `Enter` | Conversa, Canal | Отправить набранный текст |
| `Enter` | Config | Редактировать выбранный пункт или выполнить его (`Região`, `Enviar NodeInfo`); при редактировании: сохранить |
| `` ` `` (Esc) | Conversa, Canal, Config | Вернуться на Nós; при редактировании пункта Config: отменить правку |
| `Fn` + `;` | Conversa, Canal | Прокрутить историю вверх (более старые сообщения) |
| `Fn` + `.` | Conversa, Canal | Прокрутить историю вниз (более новые сообщения) |
| `del` (Backspace) | ввод текста, редактирование в Config | Удалить последний символ |
| `A` (или `a`) | только Nós | Включить или выключить автоприветствие |
| буквы, цифры, символы | ввод текста | Набор текста (только печатные символы ASCII) |

Примечания:

- Автоповтора клавиш нет. Нажимайте по одному разу на каждый символ или шаг.
- На текстовых экранах `;` и `.` без `Fn` вводятся как текст, а символ `` ` `` ввести нельзя, потому что это клавиша Esc. Остальные сочетания с `Fn` игнорируются.
- При редактировании `Potência` (мощность) принимаются только цифры.

## Экран Nós (узлы)

Список узлов, услышанных с момента запуска, плюс контакты, сохранённые в прошлых сеансах. Последний услышанный узел — наверху. Видно десять строк, список прокручивается вместе с выделением.

Каждая строка слева направо:

| Столбец | Ширина | Содержимое |
|---|---|---|
| Короткое имя | 4 | Короткое имя узла или последние 4 шестнадцатеричные цифры его номера, если его NodeInfo ещё не пришёл |
| Длинное имя | 10 | Длинное имя (обрезанное до 10 символов) или `!xxxxxxxx`, если оно неизвестно |
| Модель оборудования | 13 | Например `TBEAM`, `HELTEC_V3`, `CARDPUTER_ADV`; `HW#<n>` для моделей, которых нет в таблице прошивки; `-`, если пока ничего не известно |
| RSSI | 4 | Уровень сигнала последнего кадра от этого узла, в dBm; `-`, если не слышен с момента запуска |
| Давность | 3 | Сколько времени прошло с последнего приёма: `15s`, `2m`, `1h`, `3d`; `-`, если не слышен с момента запуска |
| `*` | 1 | Есть **непрочитанные** личные сообщения от этого узла |
| `+` | 1 | Уже **поприветствован** (автоприветствием или вручную отправленным приветствием); автоматически больше не приветствуется |

Цвета: **жёлтый** — есть непрочитанные сообщения; **белый** — его открытый ключ известен (можно сразу отправить личное сообщение); **тёмно-серый** — ключа ещё нет (личное сообщение ему ждёт ключ, см. маркер `?`).

Контакты, загруженные из флеш-памяти при запуске, показывают `-` в столбцах RSSI и давности, пока их снова не услышат.

Пустой список показывает `Nenhum nó ouvido ainda.` («Ещё не услышано ни одного узла.») и `Aguarde pacotes da rede Meshtastic.` («Ожидайте пакеты из сети Meshtastic.»). См. [Почему не видно узлов](#почему-не-видно-узлов).

Клавиши: `;`/`.` — выбор, `Enter` — открыть чат, `A` — включить/выключить автоприветствие. Строка подсказки: `Enter:conversa A:auto-saudação Tab:tela` («Enter: чат, A: автоприветствие, Tab: экран»).

## Экран Conversa (чат)

Переписка личными сообщениями (DM) с одним узлом. Откройте её клавишей `Enter` на экране Nós.

- Если узел не выбран, показывается `Escolha um nó na aba Nós (Enter).` («Выберите узел на вкладке Nós (Enter).»).
- **Строка заголовка**: `!<ID узла> <длинное имя> <модель> <семейство чипа>`, например `!9c2ea3f1 Base Station TBEAM ESP32`. В конце оранжевым выводится `(sem chave)` («нет ключа»), если открытый ключ узла ещё не известен. Если узел выпал из списка узлов (услышано более 100 узлов), заголовок показывает `!<ID узла> (fora da lista)` («нет в списке»).
- **История**: 9 строк, самая старая наверху, длинные сообщения переносятся. Полученные сообщения начинаются с `<`. Ваши сообщения начинаются с маркера состояния и `>` (см. [Маркеры сообщений](#маркеры-сообщений)). Полученный текст белый, ваш — голубой, неудачные сообщения — красные. Жёлтый `^` в правом верхнем углу означает, что вы прокрутили историю вверх. Пустая переписка показывает `(sem mensagens)` («нет сообщений»).
- **Строка ввода** внизу: `> текст_`. При открытии чата она **заранее заполнена текстом вашего приветствия** в качестве подсказки. Сотрите его клавишей `del` или просто отправьте.
- `Enter` отправляет текст как зашифрованное личное сообщение (PKI) и очищает ввод. `` ` `` — назад на Nós. `Fn`+`;` / `Fn`+`.` — прокрутка.

Отправка приветствия точно в том виде, в каком оно было подставлено, считается приветствием этого узла: он получает отметку `+`, и автоприветствие никогда его не поприветствует.

Открытие чата снимает отметку о непрочитанных сообщениях этого узла.

## Экран Canal (канал)

Публичный канал: основной канал Meshtastic по умолчанию (`LongFast`, ключ по умолчанию), который может читать любой узел с настройками по умолчанию.

- 10 строк истории. Полученные сообщения сохраняются как `<короткое имя>: <текст>` или `<последние 4 шестнадцатеричные цифры ID узла>: <текст>`, если имя отправителя неизвестно.
- `Enter` отправляет строку ввода всем в канале. Сообщения в канале не подтверждаются, поэтому ваши сообщения после отправки остаются с маркером `.`.
- `` ` `` — назад на Nós. `Fn`+`;` / `Fn`+`.` — прокрутка. Просмотр экрана снимает отметку `Canal*`.

## Экран Config

Шесть пунктов. Выберите пункт клавишами `;`/`.` и нажмите `Enter`. Строка подсказки: `Enter:editar/acionar  ;/. move` («Enter: изменить/выполнить, ;/. перемещение»). Во время редактирования над строкой ввода выводится `<пункт>: Enter salva, ` cancela` («Enter сохраняет, ` отменяет»).

| Пункт (на экране) | Значение | Что делает `Enter` |
|---|---|---|
| `Região` | Регион | Переключает на следующий регион списка (после последнего — снова первый) |
| `Potência` | Мощность передачи | Изменить мощность в dBm |
| `Nome longo` | Длинное имя | Изменить длинное имя |
| `Nome curto` | Короткое имя | Изменить короткое имя |
| `Saudação` | Приветствие | Изменить текст приветствия |
| `Enviar NodeInfo` | Отправить NodeInfo | Немедленно разослать ваш NodeInfo |

### Região (регион)

Показывает название региона и частоту LongFast, например `ANZ 919.875`. Каждое нажатие `Enter` переходит к следующему региону в порядке [таблицы регионов](frequencies.md#поддерживаемые-регионы) и **сразу перестраивает радио**. При этом заново применяется лимит мощности региона. Новый регион сохраняется через 2 секунды после последнего изменения или при выходе с экрана Config (уведомление `Config salva`). Если выключить устройство в течение этих 2 секунд, изменение пропадёт.

- Экспериментальные регионы помечены `(exp)`, например `IN 865.875 (exp)`. При выборе такого региона появляется уведомление `Fora da faixa do Cap (exp)` («вне диапазона Cap (экспериментальный)»). Пока он выбран, на экране показывается предупреждение `! Fora de 868-923 MHz do Cap (exp)` («вне диапазона Cap 868–923 MHz»). Эти частоты лежат за пределами номинального диапазона Cap, поэтому дальность может быть хуже. Используйте такой регион, только если это регион вашей страны.
- В регионах с ограничением рабочего цикла (EU_868, UA_868, TH) дополнительная строка показывает эфирное время за последний час: `Ar 1h: 12s de 360s (duty 10%)` («эфир за 1 ч: 12 с из 360 с»).
- Чтобы слышать друг друга, все узлы должны быть в одном регионе. См. [frequencies.md](frequencies.md).

### Potência (мощность передачи)

Желаемая мощность передачи, 2–22 dBm (по умолчанию 22). Введите 1 или 2 цифры и нажмите `Enter`. При недопустимом значении появляется уведомление `Potência: 2 a 22 dBm` («мощность: от 2 до 22 dBm»), а редактор остаётся открытым.

Радио использует **эффективную мощность** = min(ваша настройка, лимит региона, 22 dBm). Если эффективная мощность ниже, пункт показывает обе, например `22 dBm (efetiva 14)` («эффективная 14»). Изменение применяется сразу и сохраняется (`Config salva`).

### Nome longo / Nome curto (длинное / короткое имя)

Имена вашего узла, которые видят другие пользователи Meshtastic. Длинное имя: 1–24 байта. Короткое имя: 1–4 байта (рекомендуются латинские буквы/цифры ASCII). С клавиатуры можно вводить только ASCII. При недопустимом вводе показывается `Nome longo: 1 a 24 bytes` («длинное имя: от 1 до 24 байт») или `Nome curto: 1 a 4 letras` («короткое имя: от 1 до 4 букв»; на самом деле лимит — 1–4 байта).

После сохранения имени устройство **рассылает новый NodeInfo**, чтобы другие узлы узнали его. Между рассылками проходит не менее 30 с; если предыдущая была меньше 30 с назад, новая уйдёт, когда истекут 30 с. **Ваш ID узла и ваш ключ не меняются**: другие узлы по-прежнему узнают вас и могут отправлять вам личные сообщения. Меняется только отображаемое имя. Другие узлы обновляют имя, когда получают новый NodeInfo.

### Saudação (приветствие)

Текст, который использует автоприветствие и который подставляется в каждый новый чат, до 199 байт.

- По умолчанию он составляется из вашего длинного имени: `Saudações de <длинное имя>! 👋 (Cardputer-Adv)` («Привет от <длинное имя>! 👋»). Он следует за длинным именем при переименовании узла.
- Отредактируйте его, чтобы задать свой текст; тогда он будет отправляться точно в том виде, в каком вы его набрали.
- Сохраните **пустой** текст (или в точности текст по умолчанию), чтобы вернуться к составному тексту по умолчанию.
- При недопустимом тексте показывается `Saudação inválida` («недопустимое приветствие»).

Редактор показывает приветствие с заменами для отображения (например `?` вместо эмодзи), но сохранённый текст не меняется, пока вы его не отредактируете. Если вы редактируете приветствие по умолчанию, эмодзи сохраняется, пока вы его не удалите.

### Enviar NodeInfo (отправить NodeInfo)

Немедленно рассылает ваш NodeInfo (имена и открытый ключ) в публичный канал. Используйте эту функцию, чтобы ближайшие узлы узнали ваш ключ, например перед тем как кто-то попытается отправить вам личное сообщение.

Рассылки ограничены: **не чаще одной в 30 секунд**. Этот лимит общий с объявлением при запуске и со сменой имени. Если нажать `Enter` раньше, появится уведомление `NodeInfo em Ns` («NodeInfo через N с»), и рассылка уйдёт автоматически, когда время истечёт. Повторное нажатие не ставит в очередь вторую рассылку.

### Строка идентичности

Под пунктами, зелёным цветом: `ID !xxxxxxxx  chave aabbccdd`.

- `ID !xxxxxxxx` — ваш ID узла. Под ним другие видят вас в своих списках узлов.
- `chave aabbccdd` («ключ») — отпечаток вашего **открытого** ключа: первые 4 байта в шестнадцатеричном виде. По нему можно убедиться, что ключ не изменился после перезагрузки или обновления. Закрытый ключ никогда не показывается.
- Если ключ не удалось сохранить во флеш-памяти, здесь красным выводится `ERRO: chave não gravada na NVS!` («ОШИБКА: ключ не записан в NVS!»). См. [Устранение неполадок](#устранение-неполадок-все-состояния-и-сообщения).

Выход с экрана Config (`Tab` или `` ` ``) сохраняет отложенную смену региона. Нажатие `Tab` во время редактирования пункта отменяет правку.

## Автоприветствие

Автоприветствие отправляет ваше приветствие личным сообщением каждому новому узлу, **по одному разу на узел, навсегда**.

- **Включается и выключается клавишей `A` на экране Nós.** Строка состояния показывает `AUTO:ON` или `AUTO:OFF`. Пункта в Config для этого нет.
- Оно **ВЫКЛЮЧЕНО после каждого запуска** — намеренно, чтобы устройство никогда не начинало приветствовать людей само по себе.
- Приветствуются только узлы с **известным открытым ключом**, то есть узлы, от которых пришёл NodeInfo с ключом. Для личного сообщения нужен ключ. Серые узлы не приветствуются, пока не придёт их ключ.
- При включении в очередь также ставятся узлы с ключом, уже услышанные с момента запуска, начиная с самых свежих. Дальше узел ставится в очередь, когда приходит его NodeInfo.
- Не чаще **одного приветствия в 30 секунд**. Первое приветствие отправляется без задержки.
- В очереди помещается не более **10 узлов**. Узлы, появившиеся при полной очереди, в этот момент в неё не попадают. Они снова ставятся в очередь, когда их NodeInfo будет услышан в следующий раз (обычно узлы повторяют объявление каждые 3 часа).
- **Никогда дважды**: список поприветствованных хранится во флеш-памяти (до 500 ID узлов) и переживает перезагрузки и обновления. Ручная отправка точного текста приветствия с экрана чата тоже добавляет узел в список. Когда в списке 500 узлов, автоприветствие перестаёт приветствовать новые узлы, а не забывает старые.
- Поприветствованные узлы отмечены `+` в списке узлов.
- Выключение автоприветствия очищает очередь. Уже поприветствованные узлы остаются отмеченными.

Приветствия появляются в переписке с каждым узлом, как любые ваши личные сообщения, с обычными [маркерами](#маркеры-сообщений).

## Маркеры сообщений

Ваши сообщения начинаются с маркера состояния, за которым следует `>`. Полученные сообщения начинаются с `<`.

| Маркер | Состояние | Значение |
|---|---|---|
| `~` | в очереди | Ждёт в очереди передачи (или бюджета рабочего цикла) |
| `.` | отправлено | Радио передало его. Для личного сообщения подтверждение (пока) не пришло. Сообщения публичного канала остаются с `.`, потому что в канале нет подтверждений. |
| `v` | подтверждено | Пришёл ACK получателя: личное сообщение доставлено и расшифровано |
| `?` | ждёт ключ | Открытый ключ получателя неизвестен. Личное сообщение удерживается до прихода ключа (см. ниже). |
| `x` | ошибка | Передача не удалась (`Falha no TX`: радио сообщило об ошибке при отправке или не было готово), получатель ответил ошибкой (NAK) или на момент отправки не было ключа |

**Состояние `?`.** Личное сообщение можно зашифровать только открытым ключом получателя, а он приходит в его NodeInfo. Когда вы пишете узлу без ключа:

1. Сообщение сохраняется с `?`, и появляется уведомление `Aguardando chave do no` («ожидание ключа узла»).
2. Устройство отправляет **свой NodeInfo напрямую этому узлу с просьбой прислать в ответ его NodeInfo** (не чаще раза в минуту на узел).
3. Когда приходит NodeInfo узла, все сообщения `?` для него переходят в `~` и отправляются.

Если узел вне зоны досягаемости или не отвечает, сообщение остаётся в `?`. Когда узел станет доступен, может помочь повторная отправка или нажатие `Enviar NodeInfo`.

**Автоматических повторов нет.** Если личное сообщение осталось в `.` (без ACK), прошивка не отправляет его повторно. При необходимости наберите его снова.

## Когда устройство слушает, а когда передаёт

**Радио всегда слушает эфир**, кроме моментов передачи собственных кадров. Оно никогда не ретранслирует пакеты других узлов: устройство объявляет себя с ролью `CLIENT_MUTE` и ничего из услышанного не пересылает. Все его собственные кадры имеют лимит хопов (hop limit) 3, поэтому другие узлы mesh-сети могут их ретранслировать, как это обычно происходит в Meshtastic.

Передача происходит только в следующих случаях:

| Когда | Что | Ограничение |
|---|---|---|
| При запуске | Рассылка NodeInfo **с want_response** (соседи отвечают своими NodeInfo) | Один раз за запуск |
| Каждые 3 часа | Рассылка NodeInfo | Через 3 ч после предыдущей рассылки NodeInfo |
| Вы меняете длинное или короткое имя | Рассылка NodeInfo | Не чаще одной в 30 с (лимит общий с запуском и «Enviar NodeInfo») |
| Вы выбираете `Enviar NodeInfo` | Рассылка NodeInfo | Не чаще одной в 30 с |
| Вы отправляете сообщение | Публичный текст (Canal) или зашифрованное личное сообщение с want_ack (Conversa) | При нажатии Enter |
| Вы пишете узлу без ключа | NodeInfo напрямую этому узлу с want_response | Не чаще раза в минуту на узел |
| Автоприветствие ВКЛЮЧЕНО | Личное сообщение-приветствие узлу, чей ключ только что стал известен | Одно в 30 с, один раз на узел навсегда |
| Вы получаете личное сообщение с запросом ACK | ACK отправителю (и повторно, если отправитель повторит то же сообщение) | Один раз на полученное сообщение |
| Узел запрашивает наш NodeInfo (want_response) | NodeInfo этому узлу | Не чаще раза в 30 с в целом **и** раза в 12 ч на узел |
| Узел присылает нам зашифрованное личное сообщение, а его ключа у нас нет | NAK (`PKI_UNKNOWN_PUBKEY`) плюс наш NodeInfo с want_response, чтобы его следующую попытку можно было расшифровать | Не чаще раза в 30 с в целом и раза в 10 мин на узел |

Правила для любой передачи:

- **Один кадр за раз**, не менее **1.5 с** между концом одного кадра и началом следующего. В очереди передачи ждут не более 6 кадров.
- Каждый кадр LoRa занимает эфир примерно на **0.4–2.2 с** в зависимости от длины, обычно около **1 с** (см. [время в эфире](frequencies.md#время-в-эфире)).
- В регионах с ограничением рабочего цикла кадры ждут [бюджета эфирного времени](frequencies.md#рабочий-цикл-и-бюджет-эфирного-времени).
- Wi-Fi и Bluetooth никогда не включаются.
- Пока передаётся кадр, устройство не реагирует на клавиши (до 2.2 с).

## Почему не видно узлов

Список узлов заполняется, только когда устройство слышит кадры Meshtastic, которые оно может декодировать. Если `rx` остаётся на 0, вообще ничего не принимается. Если `rx` растёт, а список пуст, приходят кадры, которые нельзя декодировать (другой канал или ключ), либо это чужие личные сообщения.

Проверьте по порядку:

1. **Тот же регион и частота.** Все узлы должны использовать один регион. В Бразилии сообщество использует **ANZ (919.875 MHz)**, а официальный регион — **BR_902 (903.875 MHz)**. Друг друга они не слышат. Спросите местных пользователей или попробуйте другой регион и подождите. См. [frequencies.md](frequencies.md).
2. **Тот же пресет.** Эта прошивка работает только на **LongFast** — пресете Meshtastic по умолчанию. Узлы с другим пресетом (LongSlow, MediumFast, ShortFast...) используют другие параметры модема и невидимы.
3. **Публичный канал по умолчанию.** Имена узлов, открытые ключи и сообщения канала декодируются только в **основном канале по умолчанию** (`LongFast` с ключом по умолчанию `AQ==`). Узлы в приватном канале или с собственным ключом слышны (`rx` растёт), но ничего декодировать нельзя. Личные сообщения между другими узлами зашифрованы для них, и вы их тоже прочитать не можете.
4. **Дальность, высота и антенна.** Дальность LoRa зависит прежде всего от высоты и прямой видимости. В помещении, на уровне земли и в окружении зданий вы можете не услышать никого. Подойдите к окну, выйдите на балкон или на крышу. Проверьте, что антенна прикручена и стоит вертикально. См. [hardware.md](hardware.md#антенна-и-дальность).
5. **Подождите.** Узлы Meshtastic большую часть времени молчат. С настройками по умолчанию узел отправляет телеметрию примерно раз в **30 минут**, свой NodeInfo — примерно раз в **3 часа**, а координаты — периодически, если у него есть GPS и включена передача местоположения. Объявление при запуске просит соседей ответить своим NodeInfo, но отвечают только те узлы, которые его услышали. Оставьте устройство включённым на час или дольше в удачном месте.
6. **Объявите о себе.** Используйте `Enviar NodeInfo`, чтобы другие узнали о вас. Помните о лимите в 30 с.

Узел появляется в списке, как только от него услышан любой декодируемый кадр: телеметрия, координаты, текст или NodeInfo. Имя и модель появляются, а строка становится белой только после прихода его NodeInfo.

## Устранение неполадок: все состояния и сообщения

### Строка состояния

| Показано | Значение | Что делать |
|---|---|---|
| `SEM CAP LoRa` (красным) | «Нет Cap LoRa»: расширитель ввода-вывода Cap не ответил при запуске или не удалось установить выход антенного коммутатора | Выключите устройство, проверьте, что Cap плотно вставлен в разъём Cardputer-Adv, и включите снова. Во время работы прошивка повторных попыток не делает. |
| `RADIO ERRO` (красным) | «Ошибка радио»: Cap найден, но SX1262 не инициализировался | Выключите и включите питание. Если ошибка повторяется, радиомодуль может быть неисправен, или другая прошивка оставила его в плохом состоянии. Перепрошейте и попробуйте снова. |
| `duty limit` (красным) | Бюджет эфирного времени региона за последний час исчерпан, кадры ждут | Ничего не теряется. Кадры уходят по мере освобождения бюджета в течение часа. Config показывает `Ar 1h: ...`. Бюджет есть только у EU_868, UA_868 и TH. |
| `-dBm` | С момента запуска не принято ни одного кадра | См. [Почему не видно узлов](#почему-не-видно-узлов). |

Когда радио не работает, попытки передачи также вызывают уведомление `Falha no TX` (радио не готово).

### Уведомления (жёлтые, 2.5 с)

| Уведомление | Значение | Что делать |
|---|---|---|
| `Config salva` | «Настройки сохранены» во флеш-память | Ничего. |
| `ERRO ao gravar config` | «Ошибка сохранения настроек»: запись во флеш-память не удалась | Настройка действует до перезагрузки, но может быть потеряна. Попробуйте снова. Если ошибка повторяется, раздел NVS может быть заполнен или повреждён. |
| `ERRO: chave nao gravada!` (при запуске) | «Ошибка: ключ не записан»: создана новая пара ключей, но её не удалось сохранить | При следующем запуске ключ изменится, и узлы, сохранившие старый ключ, будут отвергать новый. Проверьте флеш-память/NVS (переустановите). На экране Config также показывается `ERRO: chave não gravada na NVS!`. |
| `ERRO no radio` | «Ошибка радио» при смене региона или мощности | Выключите и включите питание. Радио может работать не на показанной частоте. |
| `Fora da faixa do Cap (exp)` | «Вне диапазона Cap (экспериментальный)»: вы выбрали экспериментальный регион | Нормально, если это регион вашей страны. Ожидайте меньшей дальности. |
| `Falha no TX` | «Ошибка передачи»: радио сообщило об ошибке при отправке, или радио не готово (например, Cap не обнаружен) | Сообщение помечается `x`. Посмотрите, нет ли в строке состояния `SEM CAP LoRa` / `RADIO ERRO`, и выключите и включите питание. |
| `Texto longo demais` | «Слишком длинный текст» (больше 199 байт) | Сократите сообщение. Ввод с клавиатуры и так останавливается на 199 байтах. |
| `Fila de TX cheia` | «Очередь передачи заполнена» (ждут 6 кадров) при отправке в канал | Подождите несколько секунд и отправьте снова. В регионах с ограничением рабочего цикла кадры может задерживать бюджет. |
| `Fila de mensagens cheia` | «Очередь сообщений заполнена»: уже ждут 10 личных сообщений (например, несколько сообщений `?`) | Дождитесь прихода ключей или отправки сообщений. Личное сообщение не сохранено. |
| `Aguardando chave do no` | «Ожидание ключа узла»: личное сообщение сохранено с `?`, запрос NodeInfo отправлен | Дождитесь NodeInfo узла. См. [состояние `?`](#маркеры-сообщений). |
| `NodeInfo em Ns` | «NodeInfo через N с»: рассылка NodeInfo запрошена раньше чем через 30 с после предыдущей | Ничего. Она уйдёт автоматически. |
| `Potência: 2 a 22 dBm` | «Мощность: от 2 до 22 dBm»: недопустимое значение | Введите число от 2 до 22. |
| `Nome longo: 1 a 24 bytes` | Длинное имя пустое или слишком длинное | Введите от 1 до 24 байт. |
| `Nome curto: 1 a 4 letras` | «Короткое имя: от 1 до 4 букв»: пустое или слишком длинное (лимит — 1–4 байта) | Введите от 1 до 4 байт (рекомендуются латинские буквы/цифры ASCII). |
| `Saudação inválida` | «Недопустимое приветствие» (например, управляющие символы) | Наберите заново. Сохраните пустой текст, чтобы вернуть приветствие по умолчанию. |

### Другие ситуации

| Ситуация | Объяснение |
|---|---|
| Личное сообщение остаётся в `?` | Ключ узла не пришёл. См. [состояние `?`](#маркеры-сообщений). |
| Личное сообщение остаётся в `.` | Оно передано, но ACK не вернулся. Получатель может быть вне зоны досягаемости, или ACK потерялся. Автоматических повторов нет. |
| Сообщение показывает `x` сразу после перехода из `?` в `~` | Ключ узла пропал до отправки (например, узел был вытеснен из заполненного списка). Отправьте снова. |
| Серый узел без имени | Его кадры были услышаны, а NodeInfo — нет. Подождите или откройте чат и отправьте личное сообщение: это запросит его NodeInfo. |
| Заголовок показывает `(fora da lista)` | Этот узел вытеснен из списка на 100 узлов. Его сообщения остаются, пока их не вытеснят новые. |
| Клавиши ненадолго не реагируют | Идёт передача кадра (до 2.2 с). |
| Сообщения пропали после перезагрузки | История чатов хранится только в RAM. Имена и ключи контактов по личным сообщениям (до 50), список поприветствованных и настройки сохраняются. |

## Ограничения дисплея

Экран использует встроенный 8-битный шрифт (кодовая страница 437). Текст преобразуется **только для отображения**:

- Буквы, которые есть в шрифте, показываются с диакритикой, например `é ç ô á ü ñ`.
- Буквы с диакритикой, для которых нет глифа, показываются как базовая буква, например `ã → a`, `õ → o`, `À → A`, `Ê → E`.
- Типографские кавычки и тире превращаются в `'`, `"` и `-`.
- Эмодзи и любые другие символы без глифа показываются как `?`. Невидимые соединители и селекторы вариантов отбрасываются.

В этом шрифте нет кириллицы: русский текст в полученных сообщениях отображается знаками `?`, но сохраняется без изменений.

**То, что отправляется и хранится, никогда не изменяется.** Сообщения уходят точно в том виде, в каком набраны (UTF-8), а полученные хранятся без изменений. Сама клавиатура вводит только печатные символы ASCII.

| Параметр | Лимит |

## Часто задаваемые вопросы

**Принимает ли устройство сигналы, когда кто-то передаёт?**
Да, если отправитель в том же регионе/на той же частоте, использует пресет LongFast и находится в зоне досягаемости. Радио слушает всё время, кроме собственных коротких передач. Каждый принятый кадр увеличивает `rx` и обновляет RSSI в строке состояния, даже если прошивка не может его декодировать. В узлы и сообщения декодируются только кадры публичного канала по умолчанию и личные сообщения, адресованные вам.

**Передаёт ли моё устройство прямо сейчас?**
Только в ситуациях, перечисленных в разделе [Когда устройство слушает, а когда передаёт](#когда-устройство-слушает-а-когда-передаёт): NodeInfo при запуске, каждые 3 часа, после смены имени или `Enviar NodeInfo`, ваши собственные сообщения, автоприветствие (если ВКЛЮЧЕНО), ACK и ограниченные по частоте ответы на запросы NodeInfo. Чужой трафик оно никогда не ретранслирует. Индикатора передачи нет. Во время отправки кадра клавиатура ненадолго перестаёт реагировать. В регионах с ограничением рабочего цикла Config показывает эфирное время за последний час.

**Что такое регион ANZ?**
ANZ — регион Meshtastic для Австралии и Новой Зеландии (915–928 MHz). Частота LongFast в нём — 919.875 MHz. Бразильское сообщество Meshtastic использует ANZ, поэтому он выбран по умолчанию в этой прошивке. Официальный регион Meshtastic для Бразилии — BR_902 (903.875 MHz). Используйте регион того места, где вы находитесь; см. [frequencies.md](frequencies.md#бразилия).

**Где включается и выключается автоприветствие?**
На экране **Nós**: нажмите `A`. Строка состояния показывает `AUTO:ON` или `AUTO:OFF`. После перезагрузки оно всегда ВЫКЛЮЧЕНО. Пункта в Config для этого нет.

**Как принудительно отправить свой NodeInfo?**
Config → `Enviar NodeInfo` → `Enter`. Он уйдёт сразу или после того, как истечёт остаток 30-секундного лимита (уведомление `NodeInfo em Ns`).

**Можно ли переименовать узел?**
Да. Config → `Nome longo` (1–24 байта) и `Nome curto` (1–4 байта, рекомендуются латинские буквы/цифры ASCII). Новые имена сохраняются и объявляются новым NodeInfo. Ваш ID узла и ключ не меняются, поэтому другие узлы по-прежнему узнают вас и могут дальше отправлять вам личные сообщения.

**Можно ли использовать его с телефоном или приложением Meshtastic?**
Нет. Bluetooth и Wi-Fi выключены, а устройство настраивается только с собственной клавиатуры. По LoRa оно может общаться с телефонами, подключёнными к другим узлам Meshtastic.

**Прочитают ли мои сообщения другие?**
Сообщения публичного канала может прочитать любой, у кого настройки Meshtastic по умолчанию, — так задумано. Личные сообщения зашифрованы сквозным шифрованием открытым ключом получателя. См. [security.md](security.md).

**Ретранслирует ли устройство чужие сообщения?**
Нет. Это узел `CLIENT_MUTE`, и он никогда не пересылает пакеты других узлов.

**Почему в приветствии на экране виден `?`?**
Для эмодзи 👋 нет глифа в шрифте экрана. Отправляется он правильно. См. [Ограничения дисплея](#ограничения-дисплея).
