## 始める前に

1. **電源を入れる前に、Cap にアンテナをねじ込んで取り付けてください。** ファームウェアは起動後 1 秒以内に NodeInfo のアナウンスを送信します（初回起動時は、リージョンを確定した直後）。アンテナなしで送信すると無線部が損傷するおそれがあります。
2. M5Launcher でファームウェアをインストールします（[README のクイックスタート](../../README.ja.md#クイックスタート)と [hardware.md](hardware.md#m5launcher-でのインストール) を参照）。
3. 近くの Meshtastic ユーザーがどのリージョンを使っているかを確認してください。ブラジルではコミュニティが **ANZ**（デフォルト）を使っています。日本のリージョンは **JP**（923.375 MHz、実験的、最大 13 dBm）です。[frequencies.md](frequencies.md) を参照してください。

## 初回起動

- 初めて起動したとき、デバイスはハードウェア乱数生成器から X25519 鍵ペアを生成してフラッシュ（NVS）に保存し、トースト `Nova chave gerada`（「新しい鍵を生成しました」）を表示します。鍵ペアは再起動やアップデートをまたいで保持されます。変わるのはデバイスの NVS が消去された場合だけで、たとえばフラッシュ全体の消去や、M5Launcher 経由でインストールした一部のアプリが共有 NVS を消去した場合です。Meshtastic ノードは各ノードについて最初に受信した公開鍵を記憶する（「最初の鍵が優先」）ため、鍵が変わると、他のノードが古い鍵を忘れるまで新しい鍵を拒否し、ダイレクトメッセージのやり取りができなくなることがあります。
- **ノード ID**（`!xxxxxxxx`）はチップの工場出荷時の MAC アドレスから決まり、これも変わりません。
- デフォルトの名前は **4stro-031**（ロングネーム）と **4S31**（ショートネーム）です。Config 画面で変更できます。
- **初回起動時は、リージョンを選ぶまで何も送信されません。** 画面には `Primeiro uso: escolha a sua região`（「初回使用: リージョンを選んでください」）と表示され、ANZ が選択済みになっています。`;` / `.` でリージョンを変更し、`Enter` で確定します。その間、無線は受信のみを行います。確定するとリージョンが保存され、デバイスは近くのノードに NodeInfo を返すよう求めながら自分の NodeInfo をブロードキャストし、その後は受信を続けます。2 回目以降の起動では、保存されたリージョンですぐに始まります。保存された設定が壊れていてもリージョンが有効であれば、そのリージョンは維持されます（他の設定はデフォルトに戻ります）。有効なリージョンが保存されていなければ、再び選択画面が表示されます。
- **自動あいさつは、起動するたびにオフになります。**

## 画面レイアウト

240 × 135 のディスプレイに 40 桁のテキストが表示されます（文字列はフォントが描画するとおりに表示されます。例: `auto-saudaçao`）。

```
+----------------------------------------+
|ANZ 919.875 | AUTO:OFF | rx 42 | -97dBm |  <- ステータスバー（または黄色のトースト）
| Nós*  | Conversa |  Canal  |  Config   |  <- タブ（* = 未読あり）
|BASE Base Stati TBEAM          -97  2m* |
|JOAO Joao Movel HELTEC_V3     -112 15s +|  <- 1 行に 1 ノード
|a3f1 !9c2ea3f1  -                -   -  |
|                                        |
|Enter:conversa A:auto-saudaçao Tab:tela |  <- キーのヒント／テキスト入力
+----------------------------------------+
```

### ステータスバー

`<リージョン> <周波数> | AUTO:ON または AUTO:OFF | rx <受信フレーム数> | <最後のフレームの RSSI>`

- **リージョンと周波数**（MHz）。例: `ANZ 919.875`。無線が動作していない場合は、代わりに `SEM CAP LoRa` または `RADIO ERRO` が表示されます（[トラブルシューティング](#トラブルシューティング-すべてのステータスとメッセージ)を参照）。
- **`AUTO:ON` / `AUTO:OFF`**: 自動あいさつの状態。
- **`rx N`**: 起動以降に受信した LoRa フレームの数。無線がデコードしたすべてのフレームを数えるので、ファームウェアが読めないもの（他のチャンネルや他人どうしのダイレクトメッセージ）も含まれます。この数が増えていれば、無線は何かを受信しています。
- 最後に受信したフレームの **RSSI**。例: `-97dBm`。最初のフレームを受信するまでは `-dBm` と表示され、リージョンの送信時間予算によって送信が保留されている間は `duty limit` と表示されます。
- 行が 40 桁に収まらない場合は、`|` の前後のスペースが省かれます。
- Cap が見つからない場合、無線が故障した場合、またはデューティ制限が有効な場合、バーは**赤**になります。

**トースト**は、ステータスバーの代わりに黄色の背景で 2.5 秒間表示される短いメッセージです。例: `Config salva`（「設定を保存しました」）。

### タブ

`Nós`（ノード）、`Conversa`（チャット）、`Canal`（チャンネル）、`Config`（設定）。選択中のタブは強調表示されます。いずれかのノードに未読のダイレクトメッセージがあると `Nós` は `Nós*` に、公開チャンネルに未読メッセージがあると `Canal` は `Canal*` になります。

## キー操作

| キー | 場所 | 動作 |
|---|---|---|
| `Tab` | どこでも | 次の画面へ: Nós → Conversa → Canal → Config → Nós |
| `;` | Nós、Config | 選択を上に移動（`;` キーには上矢印が刻印されています） |
| `.` | Nós、Config | 選択を下に移動（`.` キーには下矢印が刻印されています） |
| `Enter` | Nós | 選択したノードとの会話を開く |
| `Enter` | Conversa、Canal | 入力したテキストを送信 |
| `Enter` | Config | 選択した項目を編集、または実行（`Região`、`Enviar NodeInfo`）。編集中は保存 |
| `` ` ``（Esc） | Conversa、Canal、Config | Nós に戻る。Config の項目を編集中は編集を取り消す |
| `Fn` + `;` | Conversa、Canal | 履歴を上にスクロール（古いメッセージ） |
| `Fn` + `.` | Conversa、Canal | 履歴を下にスクロール（新しいメッセージ） |
| `del`（Backspace） | テキスト入力、Config の編集中 | 最後の 1 文字を削除 |
| `A`（または `a`） | Nós のみ | 自動あいさつのオン／オフ |
| 英字、数字、記号 | テキスト入力 | 入力（印字可能な ASCII のみ） |

注意:

- キーはオートリピートしません。1 文字または 1 ステップごとに 1 回押してください。
- テキスト画面では、`Fn` なしの `;` と `.` は文字として入力されます。また `` ` `` は Esc キーなので、この文字は入力できません。その他の `Fn` との組み合わせは無視されます。
- `Potência`（出力）の編集中は、数字だけを入力できます。

## Nós (ノード) 画面

起動以降に受信したノードと、以前のセッションで保存された相手の一覧です。最も新しく受信したノードが一番上に表示されます。表示されるのは 10 行で、選択に合わせて一覧がスクロールします。

各行の内容（左から右へ）:

| 列 | 幅 | 内容 |
|---|---|---|
| ショートネーム | 4 | ノードのショートネーム。NodeInfo をまだ受信していない場合はノード番号の下位 4 桁（16 進） |
| ロングネーム | 10 | ロングネーム（10 文字で切り詰め）。不明な場合は `!xxxxxxxx` |
| ハードウェアモデル | 13 | 例: `TBEAM`、`HELTEC_V3`、`CARDPUTER_ADV`。ファームウェアの表にないモデルは `HW#<n>`、まだ何も分からない場合は `-` |
| RSSI | 4 | そのノードから最後に受信したフレームの信号強度（dBm）。起動以降に受信していなければ `-` |
| 経過時間 | 3 | 最後に受信してからの時間: `15s`、`2m`、`1h`、`3d`。起動以降に受信していなければ `-` |
| `*` | 1 | このノードからの**未読**ダイレクトメッセージあり |
| `+` | 1 | **あいさつ済み**（自動あいさつ、または手動であいさつ文を送信）。今後、自動であいさつすることはありません |

色: **黄色** = 未読メッセージあり。**白** = 公開鍵が分かっている（すぐに DM を送れる）。**濃い灰色** = 鍵がまだない（そのノードへの DM は鍵を待ちます。`?` マーカーを参照）。

起動時にフラッシュから読み込まれた相手は、再び受信されるまで RSSI と経過時間が `-` と表示されます。

一覧が空のときは `Nenhum nó ouvido ainda.`（「まだノードを受信していません。」）と `Aguarde pacotes da rede Meshtastic.`（「Meshtastic ネットワークからのパケットを待っています。」）と表示されます。[ノードが表示されない理由](#ノードが表示されない理由)を参照してください。

キー: `;`/`.` で選択、`Enter` でチャットを開く、`A` で自動あいさつを切り替え。ヒント行には `Enter:conversa A:auto-saudação Tab:tela`（「Enter: チャット、A: 自動あいさつ、Tab: 画面」）と表示されます。

## Conversa (チャット) 画面

1 つのノードとのダイレクトメッセージ（DM）の会話です。Nós 画面で `Enter` を押して開きます。

- ノードを選んでいない場合は `Escolha um nó na aba Nós (Enter).`（「Nós タブでノードを選んでください（Enter）。」）と表示されます。
- **ヘッダー行**: `!<ノード ID> <ロングネーム> <モデル> <チップファミリー>`。例: `!9c2ea3f1 Base Station TBEAM ESP32`。ノードの公開鍵がまだ分からない場合は、末尾にオレンジ色で `(sem chave)`（「鍵なし」）と表示されます。ノードがノード一覧から外れた場合（100 を超えるノードを受信したとき）、ヘッダーは `!<ノード ID> (fora da lista)`（「一覧にない」）と表示されます。
- **履歴**: 9 行で、古いものが上です。長いメッセージは折り返されます。受信したメッセージは `<` で始まります。自分のメッセージは状態マーカーと `>` で始まります（[メッセージマーカー](#メッセージマーカー)を参照）。受信したテキストは白、自分のテキストはシアン、送信に失敗したメッセージは赤で表示されます。右上の黄色の `^` は、上にスクロールしていることを示します。空の会話には `(sem mensagens)`（「メッセージなし」）と表示されます。
- 一番下の**入力行**: `> text_`。チャットを開くと、候補として**あいさつ文があらかじめ入力されています**。`del` で消すか、そのまま送信してください。
- `Enter` でテキストを暗号化 DM（PKI）として送信し、入力をクリアします。`` ` `` で Nós に戻ります。`Fn`+`;` / `Fn`+`.` でスクロールします。

あらかじめ入力されたあいさつ文をそのまま送信すると、そのノードにあいさつしたことになります。ノードに `+` が付き、自動あいさつがそのノードにあいさつすることはありません。

チャットを開くと、そのノードの未読マークが消えます。

## Canal (チャンネル) 画面

公開チャンネルです。Meshtastic のデフォルトのプライマリチャンネル（`LongFast`、デフォルト鍵）で、デフォルト設定のノードなら誰でも読めます。

- 履歴は 10 行です。受信したメッセージは `<ショートネーム>: <テキスト>` として保存されます。送信者の名前が分からない場合は `<ノード ID の下位 4 桁（16 進）>: <テキスト>` になります。
- `Enter` で入力行をチャンネルの全員に送信します。チャンネルのメッセージには ACK がないため、自分のメッセージは送信後も `.` のままです。
- `` ` `` で Nós に戻ります。`Fn`+`;` / `Fn`+`.` でスクロールします。この画面を表示すると `Canal*` のマークが消えます。

## Config 画面

6 つの項目があります。`;`/`.` で選択して `Enter` を押します。ヒント行には `Enter:editar/acionar  ;/. move`（「Enter: 編集／実行、;/. 移動」）と表示されます。編集中は、入力行の上に `<項目>: Enter salva, ` cancela`（「Enter で保存、` で取り消し」）と表示されます。

| 項目（画面表示） | 意味 | `Enter` の動作 |
|---|---|---|
| `Região` | リージョン | 一覧の次のリージョンに切り替える（最後まで行くと先頭に戻る） |
| `Potência` | 送信出力 | 出力（dBm）を編集 |
| `Nome longo` | ロングネーム | ロングネームを編集 |
| `Nome curto` | ショートネーム | ショートネームを編集 |
| `Saudação` | あいさつ文 | あいさつ文を編集 |
| `Enviar NodeInfo` | NodeInfo を送信 | 今すぐ NodeInfo をブロードキャスト |

### Região (リージョン)

リージョン名と LongFast の周波数が表示されます。例: `ANZ 919.875`。`Enter` を押すたびに[リージョン表](frequencies.md#サポートされているリージョン)の順で次のリージョンに移り、**すぐに無線の周波数を切り替えます**。リージョンの出力上限も適用し直します。新しいリージョンは、最後の変更から 2 秒後、または Config 画面を離れたときに保存されます（トースト `Config salva`）。その 2 秒以内に電源を切ると、変更は失われます。新しいリージョンが保存されるまでは何も送信されません。キュー内のフレームは待機するので、切り替えの途中で通過しただけのリージョンで送信されることはありません。

- 実験的リージョンには `(exp)` が付きます。例: `IN 865.875 (exp)`。選択すると、トースト `Fora da faixa do Cap (exp)`（「Cap の帯域外（実験的）」）が表示されます。選択中は、画面に警告 `! Fora de 868-923 MHz do Cap (exp)`（「Cap の 868–923 MHz の範囲外」）が表示されます。これらの周波数は Cap の定格帯域外なので、通信距離が短くなる可能性があります。お住まいの国のリージョンである場合にのみ使用してください。日本の **JP**（`JP 923.375 (exp)`）もこれに該当します。
- デューティサイクル制限のあるリージョン（EU_868、UA_868、TH）では、直近 1 時間に使った送信時間が追加の行に表示されます: `Ar 1h: 12s de 360s (duty 10%)`（「送信時間 1 時間: 360 秒中 12 秒」）。
- 互いに受信できるようにするには、すべてのノードが同じリージョンである必要があります。[frequencies.md](frequencies.md) を参照してください。

### Potência (送信出力)

希望する送信出力で、2–22 dBm（デフォルト 22）です。1 桁または 2 桁を入力して `Enter` を押します。無効な値を入力すると、トースト `Potência: 2 a 22 dBm`（「出力: 2〜22 dBm」）が表示され、編集画面は開いたままになります。

無線が使うのは**実効出力** = min(設定値, リージョンの上限, 22 dBm) です。実効出力のほうが低い場合は、両方が表示されます。例: `22 dBm (efetiva 14)`（「実効 14」）。日本の JP では `22 dBm (efetiva 13)` となります。変更はすぐに適用され、保存されます（`Config salva`）。

### Nome longo / Nome curto (ロングネーム / ショートネーム)

他の Meshtastic ユーザーに表示される、あなたのノードの名前です。ロングネーム: 1–24 バイト。ショートネーム: 1–4 バイト（ASCII の英字／数字を推奨）。キーボードで入力できるのは ASCII だけです。無効な入力では `Nome longo: 1 a 24 bytes`（「ロングネーム: 1〜24 バイト」）または `Nome curto: 1 a 4 letras`（「ショートネーム: 1〜4 文字」。実際の上限は 1–4 バイト）と表示されます。

名前を保存すると、他のノードが新しい名前を知ることができるよう、デバイスは**新しい NodeInfo をブロードキャストします**。ブロードキャストの間隔は最低 30 秒です。前回から 30 秒経っていない場合は、30 秒経過した時点で送信されます。**ノード ID と鍵は変わりません**。他のノードは引き続きあなたを認識し、DM を送ることができます。変わるのは表示名だけです。他のノードは新しい NodeInfo を受信した時点で名前を更新します。

### Saudação (あいさつ文)

自動あいさつで使われ、新しいチャットごとにあらかじめ入力されるテキストで、最大 199 バイトです。

- デフォルトでは、ロングネームから `Saudações de <ロングネーム>! 👋 (Cardputer-Adv)`（「<ロングネーム> からごあいさつ！ 👋」）という文が作られます。ノード名を変えると、それに合わせて変わります。
- 編集すると独自のテキストを設定でき、入力したとおりに送信されます。
- **空の**テキスト（またはデフォルトとまったく同じテキスト）を保存すると、自動生成されるデフォルトに戻ります。
- 無効なテキストでは `Saudação inválida`（「無効なあいさつ文」）と表示されます。

編集画面には表示用の置き換えを行ったあいさつ文（たとえば絵文字の代わりに `?`）が表示されますが、保存されたテキストは編集しない限り変わりません。デフォルトのあいさつ文を編集する場合も、絵文字を削除しなければそのまま残ります。

### Enviar NodeInfo (NodeInfo を送信)

自分の NodeInfo（名前と公開鍵）を公開チャンネルですぐにブロードキャストします。近くのノードにあなたの鍵を知らせたいとき、たとえば誰かがあなたに DM を送ろうとする前に使ってください。

ブロードキャストは **30 秒に 1 回**までに制限されています。この制限は、起動時のアナウンスや名前の変更と共通です。それより早く `Enter` を押すと、トースト `NodeInfo em Ns`（「N 秒後に NodeInfo」）が表示され、時間になると自動的に送信されます。もう一度押しても 2 回目はキューに入りません。

### 識別情報の行

項目の下に緑色で表示されます: `ID !xxxxxxxx  chave aabbccdd`

- `ID !xxxxxxxx` はあなたのノード ID です。他の人のノード一覧にはこのように表示されます。
- `chave aabbccdd`（「鍵」）は、あなたの**公開**鍵のフィンガープリントで、先頭 4 バイトを 16 進で表したものです。再起動やアップデートの後に鍵が変わっていないことを確認できます。秘密鍵は決して表示されません。
- 鍵をフラッシュに保存できなかった場合、この部分には赤で `ERRO: chave não gravada na NVS!`（「エラー: 鍵が NVS に保存されていません！」）と表示されます。[トラブルシューティング](#トラブルシューティング-すべてのステータスとメッセージ)を参照してください。

Config 画面を離れると（`Tab` または `` ` ``）、保留中のリージョン変更が保存されます。項目の編集中に `Tab` を押すと、編集内容は破棄されます。

## 自動あいさつ

自動あいさつは、新しいノードそれぞれにあいさつ文を DM で送ります。**1 つのノードにつき一度だけで、二度と送りません**。

- **Nós 画面で `A` を押してオン／オフを切り替えます。** ステータスバーに `AUTO:ON` または `AUTO:OFF` と表示されます。Config には項目がありません。
- 設計上、**起動するたびにオフ**になります。デバイスが勝手に人にあいさつを始めることはありません。
- あいさつするのは**公開鍵が分かっている**ノード、つまり鍵を含む NodeInfo を受信したノードだけです。DM には鍵が必要です。灰色で表示されているノードには、鍵が届くまであいさつしません。
- オンにすると、起動以降に受信して鍵が分かっているノードも、新しいものから順にキューに入ります。その後は、NodeInfo が届いた時点でノードがキューに入ります。
- あいさつは最大で **30 秒に 1 件**です。最初のあいさつは待たずに送られます。
- キューに入るのは最大 **10 ノード**です。キューがいっぱいのときに届いたノードは、その時点ではキューに入りません。次にそのノードの NodeInfo を受信したときに改めてキューに入ります（ノードは通常 3 時間ごとに再アナウンスします）。
- **二度と送らない**: あいさつ済みの一覧はフラッシュに保存され（最大 500 ノード ID）、再起動やアップデートをまたいで保持されます。チャット画面から正確なあいさつ文を手動で送った場合も、そのノードは一覧に追加されます。一覧が 500 ノードに達すると、古いものを忘れる代わりに、新しいノードへの自動あいさつを止めます。
- あいさつ済みのノードは、ノード一覧に `+` が表示されます。
- 自動あいさつをオフにするとキューがクリアされます。すでにあいさつしたノードはあいさつ済みのままです。

あいさつは、通常の DM と同じように各ノードの会話に表示され、いつもの[マーカー](#メッセージマーカー)が付きます。

## メッセージマーカー

自分のメッセージは状態マーカーと、それに続く `>` で始まります。受信したメッセージは `<` で始まります。

| マーカー | 状態 | 意味 |
|---|---|---|
| `~` | キュー内 | 送信キューで待機中（またはデューティサイクルの予算待ち） |
| `.` | 送信済み | 無線が送信した。DM の場合、ACK は（まだ）届いていない。公開チャンネルには ACK がないため、チャンネルのメッセージは `.` のまま |
| `v` | 確認済み | 受信者の ACK が返ってきた: DM は届き、復号された |
| `?` | 鍵待ち | 受信者の公開鍵が分からない。DM は鍵が届くまで最大 10 分間保留される（下記参照） |
| `x` | 失敗 | 送信に失敗した（`Falha no TX`: 送信中に無線がエラーを報告した）、受信者がエラー（NAK）を返した、送信時に鍵がなかった、または 10 分以内に鍵が届かなかった |

**`?` の状態について。** DM は受信者の公開鍵でしか暗号化できず、その鍵は受信者の NodeInfo に含まれています。鍵のないノードに送信すると、次のようになります。

1. メッセージは `?` の状態で保存され、トースト `Aguardando chave do no`（「ノードの鍵を待っています」）が表示されます。
2. デバイスは**自分の NodeInfo をそのノードに直接送り、相手の NodeInfo を返すよう求めます**（1 ノードにつき 1 分に 1 回まで）。
3. そのノードの NodeInfo が届くと、そのノード宛ての `?` のメッセージはすべて `~` に変わり、送信されます。

メッセージが `?` の間、デバイスはそのノードへの NodeInfo の要求を最大 1 分に 1 回繰り返します。**10 分**以内に鍵が届かなければ、メッセージは `x` になります。また、10 件の DM キューがいっぱいのときに鍵の分かっているノードへ DM を送った場合も、最も古い `?` のメッセージが場所を譲って `x` になります。相手と通信できるようになったら、再送するか `Enviar NodeInfo` を押すと解決することがあります。

**自動再送はありません。** DM が `.` のまま（ACK なし）でも、ファームウェアは再送しません。必要なら入力し直してください。

## デバイスが受信するときと送信するとき

**無線は、自分のフレームを送信している間を除いて、常に受信しています。** 他のノードのパケットを中継することはありません。デバイスはロール `CLIENT_MUTE` として自身をアナウンスし、受信したものを再ブロードキャストしません。自分のフレームはすべてホップリミット 3 を使うので、通常の Meshtastic と同様に、メッシュ内の他のノードがそれを中継することがあります。

送信するのは次の場合だけです。

| タイミング | 内容 | 制限 |
|---|---|---|
| 起動時 | **want_response 付き**の NodeInfo ブロードキャスト（近くのノードが自分の NodeInfo で応答する） | 起動ごとに 1 回 |
| 3 時間ごと | NodeInfo ブロードキャスト | 前回の NodeInfo ブロードキャストから 3 時間後 |
| ロングネームまたはショートネームを変更したとき | NodeInfo ブロードキャスト | 最大 30 秒に 1 回（起動時と「Enviar NodeInfo」と共通） |
| `Enviar NodeInfo` を選んだとき | NodeInfo ブロードキャスト | 最大 30 秒に 1 回 |
| メッセージを送ったとき | 公開テキスト（Canal）、または want_ack 付きの暗号化 DM（Conversa） | Enter を押したとき |
| 鍵のないノードに DM を送ったとき | want_response 付きの NodeInfo をそのノードに直接送信 | 1 ノードにつき最大 1 分に 1 回 |
| 自動あいさつがオンのとき | 新たに鍵が分かったノードへのあいさつ DM | 30 秒に 1 件、1 ノードにつき生涯 1 回 |
| ACK を求める DM を受信したとき | 送信者への ACK（送信者が同じ DM を再送した場合にも再度送る） | 受信した DM ごとに 1 回、さらにその再送に対して最大 2 回 |
| ノードがこちらの NodeInfo を求めたとき（want_response） | そのノードへの NodeInfo | 全体で最大 30 秒に 1 回、**かつ** 1 ノードにつき 12 時間に 1 回 |
| 鍵を持っていないノードから暗号化 DM が届いたとき | NAK（`PKI_UNKNOWN_PUBKEY`）と want_response 付きの自分の NodeInfo。相手の次の試行を復号できるようにするため | 全体で最大 30 秒に 1 回、かつ 1 ノードにつき 10 分に 1 回 |

すべての送信に適用されるルール:

- **一度に 1 フレーム**で、1 つのフレームの終わりから次のフレームの始まりまで最低 **1.5 秒**空けます。送信キューで待機できるのは最大 6 フレームです。
- LoRa フレーム 1 つが電波を占有する時間は長さに応じて約 **0.4–2.2 秒**で、通常は約 **1 秒**です（[送信時間](frequencies.md#送信時間)を参照）。
- デューティサイクルのあるリージョンでは、フレームは[送信時間の予算](frequencies.md#デューティサイクルと送信時間の予算)を待ちます。
- Wi-Fi と Bluetooth がオンになることはありません。
- フレームの送信中、デバイスはキーに反応しません（最大約 2.2 秒）。

## ノードが表示されない理由

ノード一覧は、デバイスがデコードできる Meshtastic のフレームを受信したときにだけ増えます。`rx` が 0 のままなら、まったく何も受信していません。`rx` は増えるのに一覧が空のままなら、デコードできないフレーム（別のチャンネルや鍵）か、他人どうしのダイレクトメッセージが届いています。

次の順に確認してください。

1. **同じリージョンと周波数。** すべてのノードが同じリージョンを使う必要があります。ブラジルではコミュニティが **ANZ（919.875 MHz）** を使い、公式リージョンは **BR_902（903.875 MHz）** です。この 2 つは互いに受信できません。地元のユーザーに聞くか、もう一方のリージョンを試して待ってください。日本では **JP（923.375 MHz）** です。[frequencies.md](frequencies.md) を参照してください。
2. **同じプリセット。** このファームウェアが使えるのは Meshtastic のデフォルトである **LongFast** だけです。他のプリセット（LongSlow、MediumFast、ShortFast など）に設定されたノードはモデムの設定が異なるため、見えません。
3. **デフォルトの公開チャンネル。** ノード名、公開鍵、チャンネルのメッセージがデコードされるのは**デフォルトのプライマリチャンネル**（`LongFast`、デフォルト鍵 `AQ==`）だけです。プライベートチャンネルや独自の鍵を使うノードの電波は受信されます（`rx` は増える）が、何もデコードできません。他のノードどうしの DM はそれぞれのために暗号化されているので、これも読めません。
4. **通信距離、高さ、アンテナ。** LoRa の通信距離は主に高さと見通しで決まります。屋内の地上階で建物に囲まれていると、誰も受信できないことがあります。窓際、ベランダ、屋上に移動してください。アンテナがねじ込まれていて垂直になっているか確認してください。[hardware.md](hardware.md#アンテナと通信距離) を参照してください。
5. **時間をかける。** Meshtastic のノードはほとんどの時間、何も送信していません。デフォルト設定では、テレメトリは約 **30 分**ごと、NodeInfo は約 **3 時間**ごと、位置情報は GPS があり位置の共有がオンの場合に定期的に送られます。起動時のアナウンスは近くのノードに NodeInfo で応答するよう求めますが、応答するのはそれを受信したノードだけです。条件の良い場所で 1 時間以上電源を入れたままにしてください。
6. **自分をアナウンスする。** `Enviar NodeInfo` を使って、他のノードにあなたのことを知らせてください。30 秒の制限に注意してください。

ノードは、そのノードからデコード可能なフレーム（テレメトリ、位置、テキスト、NodeInfo）を 1 つでも受信すると、すぐに一覧に表示されます。名前とモデルが表示され、白くなるのは、NodeInfo が届いてからです。

## トラブルシューティング すべてのステータスとメッセージ

### ステータスバー

| 表示 | 意味 | 対処 |
|---|---|---|
| `SEM CAP LoRa`（赤） | 「LoRa Cap なし」: 起動時に Cap の I/O エキスパンダが応答しなかった、またはアンテナスイッチの出力を設定できなかった | 電源を切り、Cap が Cardputer-Adv のコネクタにしっかり差し込まれているか確認してから、再び電源を入れてください。実行中にファームウェアが再試行することはありません。 |
| `RADIO ERRO`（赤） | 「無線エラー」: Cap は見つかったが、SX1262 が初期化されなかった | 電源を入れ直してください。解決しない場合は、無線モジュールの故障か、別のファームウェアが異常な状態のままにした可能性があります。書き込み直して再度試してください。 |
| `duty limit`（赤） | 直近 1 時間のリージョンの送信時間予算を使い切り、フレームが待機している | 何も失われません。1 時間以内に予算が空くにつれてフレームが送信されます。Config に `Ar 1h: ...` が表示されます。予算があるのは EU_868、UA_868、TH だけです。 |
| `-dBm` | 起動以降、フレームを受信していない | [ノードが表示されない理由](#ノードが表示されない理由)を参照してください。 |

無線が動作していないとき（`SEM CAP LoRa` または `RADIO ERRO`）は何も送信されません。フレームはキューで待機し（自分のメッセージは `~` のまま）、失敗としては扱われません。

### トースト (黄色、2.5 秒)

| トースト | 意味 | 対処 |
|---|---|---|
| `Config salva` | フラッシュに「設定を保存しました」 | 何もする必要はありません。 |
| `ERRO ao gravar config` | 「設定の保存エラー」: フラッシュへの書き込みに失敗した | 設定は再起動までは有効ですが、失われる可能性があります。もう一度試してください。失敗が続く場合は、NVS パーティションがいっぱいか壊れている可能性があります。 |
| `ERRO: chave nao gravada!`（起動時） | 「エラー: 鍵が保存されていません」: 新しい鍵ペアを生成したが保存できなかった | 次回の起動時に鍵が変わり、古い鍵を保存したノードは新しい鍵を拒否します。フラッシュ／NVS を確認してください（再インストール）。Config にも `ERRO: chave não gravada na NVS!` と表示されます。 |
| `Nova chave gerada`（起動時） | 「新しい鍵を生成しました」: 鍵ペアが保存されていなかった（初回起動、または NVS が消去された）ため、新しく作成して保存した | 初回起動なら何もする必要はありません。後から表示された場合は NVS が消去されています。古い鍵を保存したノードは、それを忘れるまで新しい鍵を拒否することがあります。 |
| `ERRO no radio` | リージョンまたは出力の変更中の「無線エラー」 | 電源を入れ直してください。無線が表示どおりの周波数になっていない可能性があります。 |
| `Fora da faixa do Cap (exp)` | 「Cap の帯域外（実験的）」: 実験的リージョンを選択した | お住まいの国のリージョンであれば問題ありません。通信距離は短くなると考えてください。 |
| `Falha no TX` | 「送信失敗」: 送信中に無線がエラーを報告した | メッセージに `x` が付きます。もう一度送ってください。繰り返し起きる場合は電源を入れ直してください。 |
| `Texto longo demais` | 「テキストが長すぎます」（199 バイト超） | メッセージを短くしてください。キーボード入力はもともと 199 バイトで止まります。 |
| `Fila de TX cheia` | チャンネルへの送信時に「送信キューがいっぱい」（6 フレーム待機中） | 数秒待ってから再送してください。デューティサイクルのあるリージョンでは、予算によってフレームが保留されている可能性があります。 |
| `Fila de mensagens cheia` | 「メッセージキューがいっぱい」: すでに 10 件の DM が待機している（たとえば `?` のメッセージが複数） | 鍵が届くか、メッセージが送信されるのを待ってください。`?` のメッセージは 10 分で諦められ、鍵の分かっているノードへの DM は最も古い `?` のメッセージと置き換わります。この DM は保存されていません。 |
| `Aguardando chave do no` | 「ノードの鍵を待っています」: DM を `?` で保存し、NodeInfo の要求を送った | ノードの NodeInfo を待ってください。[`?` の状態](#メッセージマーカー)を参照してください。 |
| `NodeInfo em Ns` | 「N 秒後に NodeInfo」: 前回から 30 秒以内に NodeInfo のブロードキャストが要求された | 何もする必要はありません。自動的に送信されます。 |
| `Potência: 2 a 22 dBm` | 「出力: 2〜22 dBm」: 無効な値 | 2 から 22 までの数を入力してください。 |
| `Nome longo: 1 a 24 bytes` | ロングネームが空、または長すぎる | 1–24 バイトで入力してください。 |
| `Nome curto: 1 a 4 letras` | 「ショートネーム: 1〜4 文字」: 空、または長すぎる（上限は 1–4 バイト） | 1–4 バイトで入力してください（ASCII の英字／数字を推奨）。 |
| `Saudação inválida` | 「無効なあいさつ文」（たとえば制御文字を含む） | 入力し直してください。空のテキストを保存するとデフォルトに戻ります。 |

### その他の状況

| 状況 | 説明 |
|---|---|
| DM が `?` のまま | ノードの鍵が届いていません。[`?` の状態](#メッセージマーカー)を参照してください。 |
| DM が `.` のまま | 送信はされたが ACK が返ってきていません。受信者が範囲外にいるか、ACK が失われた可能性があります。自動再送はありません。 |
| `?` が `~` に変わった直後に DM が `x` になる | 送信前にノードの鍵が消えました（たとえば、いっぱいになった一覧からノードが追い出された）。もう一度送ってください。 |
| 保存済みの相手がデバイスをリセットし、DM が使えなくなった | このデバイスはその相手について最初に保存した鍵を保持し、新しい鍵を無視します。[よくある質問](#よくある質問)を参照してください。 |
| 名前のない灰色のノード | そのノードのフレームは受信したが、NodeInfo は受信していません。待つか、チャットを開いて DM を送ってください。それにより NodeInfo が要求されます。 |
| ヘッダーに `(fora da lista)` と表示される | そのノードは 100 ノードの一覧から追い出されました。そのメッセージは押し出されるまで残ります。 |
| 一瞬キーが効かない | フレームを送信中です（最大約 2.2 秒）。 |
| 再起動後にメッセージが消えた | チャット履歴は RAM にしかありません。DM の相手の名前と鍵（最大 50）、あいさつ済みの一覧、設定は保持されます。 |

## 表示の制限

画面は内蔵の 8 ビットフォント（コードページ 437）を使います。テキストの変換は**表示のためだけ**に行われます。

- フォントにある文字は、アクセント付きで表示されます。例: `é ç ô á ü ñ`
- グリフのないアクセント付き文字は、元の文字で表示されます。例: `ã → a`、`õ → o`、`À → A`、`Ê → E`
- 曲がった引用符やダッシュは `'`、`"`、`-` になります。
- 絵文字や、グリフのないその他の文字（日本語の文字を含む）は `?` と表示されます。不可視の結合文字や異体字セレクタは取り除かれます。

**送信・保存される内容は決して変更されません。** メッセージは入力したとおりに（UTF-8 で）送信され、受信したメッセージもそのまま保持されます。キーボードで入力できるのは印字可能な ASCII だけです。

## 制限値

| 項目 | 上限 |
|---|---|
| メッセージのテキスト | **199 バイト**（UTF-8。アクセント付き文字は 2 バイト、日本語の文字は通常 3 バイト、絵文字は 4 バイト） |
| ロングネーム / ショートネーム | 1–24 バイト / 1–4 バイト（ASCII の英字／数字を推奨） |
| あいさつ文 | 199 バイト |
| 会話ごとのメッセージ数 | 30（古いものから削除）。全会話の合計で 96。RAM のみ |
| 一覧のノード数 | 100（最後に受信したのが最も古いノードから削除） |
| フラッシュに保存される相手（名前 + 鍵） | 50（DM をやり取りしたノード） |
| あいさつ済みの一覧 | 500 ノード |
| 待機中の DM（キュー内または `?`） | 10 |
| 送信キュー | 6 フレーム |
| 自動あいさつのキュー | 10 ノード |
| 送信出力 | 2–22 dBm、リージョンの上限で制限 |
| DM の再送 | なし |

## よくある質問

**誰かが送信したとき、その電波を受信しますか？**
はい。送信者が同じリージョン／周波数と LongFast プリセットを使い、通信範囲内にいれば受信します。無線は、自分の短い送信の間を除いて常に受信しています。受信したフレームはすべて、ファームウェアがデコードできない場合でも `rx` を増やし、ステータスバーの RSSI を更新します。ノードやメッセージとしてデコードされるのは、デフォルトの公開チャンネルのフレームと、あなた宛ての DM だけです。

**今、デバイスは送信していますか？**
[デバイスが受信するときと送信するとき](#デバイスが受信するときと送信するとき)に挙げた場合だけです: 起動時の NodeInfo、3 時間ごと、名前の変更や `Enviar NodeInfo` の後、自分のメッセージ、自動あいさつ（オンの場合）、ACK、そして回数制限付きの NodeInfo 要求への応答です。他人のトラフィックを中継することはありません。送信インジケーターはありません。フレームの送信中は、キーボードが一瞬反応しなくなります。デューティサイクルのあるリージョンでは、Config に直近 1 時間の送信時間が表示されます。

**ANZ リージョンとは何ですか？**
ANZ はオーストラリアとニュージーランド向けの Meshtastic リージョン（915–928 MHz）です。そこでの LongFast の周波数は 919.875 MHz です。ブラジルの Meshtastic コミュニティが ANZ を使っているため、このファームウェアのデフォルトになっています。ブラジルの公式 Meshtastic リージョンは BR_902（903.875 MHz）です。今いる場所のリージョンを使ってください。日本では JP です。[frequencies.md](frequencies.md#ブラジル) を参照してください。

**自動あいさつのオン／オフはどこにありますか？**
**Nós** 画面で `A` を押します。ステータスバーに `AUTO:ON` または `AUTO:OFF` と表示されます。再起動後は必ずオフになります。Config には項目がありません。

**NodeInfo を強制的に送るには？**
Config → `Enviar NodeInfo` → `Enter`。すぐに、または 30 秒の制限の残り時間が過ぎた後に送信されます（トースト `NodeInfo em Ns`）。

**ノードの名前を変えられますか？**
はい。Config → `Nome longo`（1–24 バイト）と `Nome curto`（1–4 バイト、ASCII の英字／数字を推奨）。新しい名前は保存され、新しい NodeInfo でアナウンスされます。ノード ID と鍵は変わらないので、他のノードは引き続きあなたを認識し、DM を送り続けることができます。

**スマートフォンや Meshtastic アプリと一緒に使えますか？**
いいえ。Bluetooth と Wi-Fi はオフで、デバイスの設定は本体のキーボードからしか行えません。他の Meshtastic ノードに接続されたスマートフォンとは、LoRa 経由でやり取りできます。

**自分のメッセージは他の人に読まれますか？**
公開チャンネルのメッセージは、設計上、デフォルト設定の Meshtastic を使っている人なら誰でも読めます。DM は受信者の公開鍵でエンドツーエンド暗号化されます。[security.md](security.md) を参照してください。

**他の人のメッセージを中継しますか？**
いいえ。`CLIENT_MUTE` ノードなので、他のノードのパケットを再ブロードキャストすることはありません。

**画面のあいさつ文に `?` が表示されるのはなぜですか？**
絵文字 👋 のグリフが画面のフォントにないためです。送信は正しく行われます。[表示の制限](#表示の制限)を参照してください。

**相手がデバイスをリセットし（新しい鍵）、DM が使えなくなりました。どうすればよいですか？**

このファームウェアは、DM の相手（最大 50）ごとに最初に保存した公開鍵を保持し、そのノード番号に対する他の鍵は、相手が 100 ノードの一覧から外れた後でも無視します。これはなりすましからあなたを守りますが、相手が工場出荷時の状態にリセットしたり NVS を消去したりして新しい鍵を得た場合、このデバイスはその鍵を拒否し続けます。相手はあなたの DM を復号できず、あなたも相手の DM を復号できません。v1 には保存済みの鍵を 1 つだけ忘れる操作はありません（「ノードの鍵を忘れる」操作は[ロードマップ](roadmap.md)にあります）。現時点で解決する唯一の方法はこのデバイスの NVS を消去することですが、そうすると自分の鍵も変わり、保存済みの相手、あいさつ済みの一覧、設定も消えます。
