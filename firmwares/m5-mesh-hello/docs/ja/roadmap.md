# ロードマップと既知の制限

v0.1.0 は意図的に小さく作られた Meshtastic ノードです。このページでは、まだできないこと、v2 のアイデア、v1 の既知の制限を挙げます。どのアイデアも約束ではありません。貢献を歓迎します（[CONTRIBUTING.md](../../CONTRIBUTING.md) を参照）。

## v2 のアイデア

| アイデア | 備考 |
|---|---|
| **GPS / 位置情報** | Cap の ATGM336H GNSS（UART、ESP RX G15 / TX G13）を使って `POSITION_APP` を送信し、他のノードまでの距離を表示する。LoRa の送信は GNSS 受信機に干渉するので、両者のスケジュールを慎重に組む必要がある。 |
| **複数のチャンネルと独自の PSK** | セカンダリチャンネル、独自の鍵、AES-256-CTR チャンネル（32 バイトの PSK）、`LongFast` 以外のチャンネル名、チャンネル URL/QR の取り込み。現在はデフォルトのプライマリチャンネルだけに対応し、`ctrCrypt` は AES-128 のみ。 |
| **他のプリセット** | LongSlow、MediumFast、ShortFast などのモデムプリセット（周波数の計算式はすでにチャンネル名と帯域幅を受け取る）。 |
| **XEdDSA の署名と検証** | 新しい Meshtastic ファームウェアと同様に、自分のパケットに署名し、他のノードの署名付きパケットを検証する。 |
| **中継 / ルーターのロール** | `CLIENT_MUTE` の代わりに、オプションで他のノードのパケットを再ブロードキャストする（ホップリミットの処理、next-hop ルーティング）。 |
| **DM の再送** | Meshtastic の reliable router と同様に、ACK が届かないときに DM を数回再送する。 |
| **UTF-8 フォント** | ポルトガル語／スペイン語／ロシア語のグリフと絵文字を含む表示フォント、およびキーボードでの非 ASCII 入力。 |
| **チャット履歴の永続化** | 再起動をまたいでメッセージを保持する（SD カードまたは NVS、上限付き）。 |
| **ノンブロッキング送信** | 割り込み駆動の送信により、最大 2.2 秒の送信時間中も UI が反応するようにする。 |
| **テレメトリ / トレースルート** | 他のノードのテレメトリを表示し、トレースルートに応答または送信する。 |
| **バッテリー表示** | v1 では使っていないバッテリーの ADC を読む。注意が必要: 鍵の生成に使う RF エントロピー源は ADC とハードウェアを共有しているので、ADC は鍵の生成後に設定しなければならない。 |
| **MeshCore?** | 別のメッシュとして MeshCore プロトコルに対応する。検討中。 |
| **識別情報の移行** | バージョン付きの鍵レコードの移行により、将来フォーマットを変更しても鍵が再生成されないようにする。 |
| **ノードの鍵を忘れる** | 保存済みの相手の鍵を 1 つ忘れる操作により、工場出荷時の状態にリセットした（新しい鍵の）相手を再び受け入れられるようにする。現在、保存された鍵は決して置き換えられない。 |

## v1 の既知の制限

| 制限 | 詳細 |
|---|---|
| **199 バイトのテキスト** | メッセージ、あいさつ文、入力行は UTF-8 で 199 バイトまで。 |
| **表示のグリフ** | CP437 フォントには一部のアクセント付き文字（アクセントなしで表示。例: `ã → a`）、すべての絵文字、日本語の文字がない（`?` と表示）。送信するテキストは決して変更されない。[ユーザーガイド](user-guide.md#表示の制限)を参照。 |
| **キーボード入力は ASCII のみ** | 入力できるのは印字可能な ASCII だけ。`` ` `` の文字は入力できない（Esc キーのため）。 |
| **ブロッキング送信で UI が止まる** | フレームの送信中（255 バイトで最大約 2.2 秒）は、キーが読み取られず、画面も更新されない。 |
| **キーリピートなし** | キーを押し続けても繰り返されない。 |
| **テキスト画面のスクロール** | 履歴は `Fn`+`;` / `Fn`+`.` で、1 回押すごとに 1 行スクロールする。 |
| **DM の再送なし** | ACK のない DM は `.` のまま。 |
| **メッセージは RAM のみ** | 会話ごとに 30 件、合計 96 件。電源を切ると消える。 |
| **RAM 上のノードは 100** | 一覧がいっぱいのときは、保存済みの相手ではない鍵なしのノードのうち最後に受信したのが最も古いものから先に削除し、それがなければ最後に受信したのが最も古いノードを削除する。保存された DM の相手（最大 50）の鍵は別の表に保持されるので、一覧から削除されても残る。 |
| **保存済みの相手の鍵は置き換えられない** | 保存済みの相手が工場出荷時の状態にリセットして新しい鍵を得ると、その鍵は拒否され、その相手との DM は使えなくなる。「ノードの鍵を忘れる」操作はまだない。[ユーザーガイドのよくある質問](user-guide.md#よくある質問)を参照。 |
| **あいさつ済みの集合は 500** | 500 ノードにあいさつした後は、誰にも二度あいさつしないよう、新しいノードへの自動あいさつを止める。 |
| **単一のチャンネルとプリセット** | デフォルトのプライマリチャンネルのみ、LongFast のみ。 |
| **署名なし** | XEdDSA は実装されていない。[security.md](security.md#保護されないもの) を参照。 |
| **スマートフォンアプリ、Wi-Fi、BLE、MQTT なし** | デバイスの設定は本体のキーボードからのみ。 |
| **物理的な鍵の抽出** | M5Launcher の下ではフラッシュ暗号化がオフなので、物理的にアクセスできれば NVS 内の秘密鍵を読み出せる。 |
| **2 秒以内のリージョン変更は失われる** | リージョンの変更は最後の変更から 2 秒後、または Config を離れたときに保存される。それより早く電源を切ると失われる。保存されるまで何も送信されない。 |
| **実行中に Cap を自動検出しない** | 起動時に Cap がない場合（`SEM CAP LoRa`）、問題を直した後にファームウェアを再起動する必要がある。 |
| **実験的リージョン** | IN、NZ_865、NP_865、KZ_863、JP、TW、TH は Cap の定格 868–923 MHz の外にあり、性能は測定されていない。日本の JP（923.375 MHz、最大 13 dBm）については [frequencies.md](frequencies.md#実験的リージョン) の注意を参照。 |
| **エンドツーエンドの相互運用性は実地で未確認** | 無線の初期化、送信、識別情報の保持、UI はデバイスで確認済み。他の Meshtastic ノードとの DM やチャンネルメッセージのやり取りは実装され、上流と互換性のあるベクタでテストされているが、実地ではまだ確認されていない。 |
