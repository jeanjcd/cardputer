# ハードウェア

M5-Mesh-Hello は、次の特定の組み合わせで動作します。

- **M5Stack Cardputer-Adv**（ESP32-S3、240 × 135 ディスプレイ、TCA8418 コントローラ経由のキーボード）。
- **M5Stack Cap LoRa-1262**: Semtech SX1262 LoRa トランシーバ、定格 868–923 MHz、最大 +22 dBm、RP-SMA アンテナコネクタ。ATGM336H GNSS 受信機も搭載していますが、v1 では使用しません。
- Cap の RP-SMA コネクタに取り付ける**アンテナ**。キット付属のアンテナは 868 MHz に調整されています（[アンテナと通信距離](#アンテナと通信距離)を参照）。

初代 Cardputer（Adv ではないもの）や他の LoRa モジュールには対応していません。ピン配置、I/O エキスパンダ、アンテナスイッチが異なるためです。

> **アンテナなしで送信しないでください。** ファームウェアは起動後 1 秒以内に NodeInfo を送信するので、電源を入れる前にアンテナをねじ込んで取り付けてください。

## ピン配置

[`src/hw/radio.cpp`](../../src/hw/radio.cpp) と M5Stack の Cap LoRa-1262 のドキュメントより:

| 信号 | ESP32-S3 のピン | 備考 |
|---|---|---|
| SX1262 NSS（チップセレクト） | G5 | |
| SX1262 DIO1（IRQ） | G4 | パケット受信時の割り込み。レベルとしてもポーリングする |
| SX1262 RESET | G3 | |
| SX1262 BUSY | G6 | |
| SPI SCK | G40 | microSD スロットと共有 |
| SPI MISO | G39 | microSD スロットと共有 |
| SPI MOSI | G14 | microSD スロットと共有 |
| microSD CS | G12 | 無線の起動前に **High**（非選択）にする |
| I²C SDA / SCL（内部バス） | G8 / G9 | キーボードコントローラ、IMU、Cap の I/O エキスパンダで共有 |
| PI4IOE5V6408 I/O エキスパンダ | I²C アドレス `0x43` | ポート **P0** がアンテナの RF スイッチを駆動 |
| GNSS UART（ATGM336H） | ESP RX = G15、ESP TX = G13、115200 baud | **v1 では未使用** |

LoRa/SD バスは ESP32-S3 の SPI2（`FSPI`）ペリフェラルで動作します。ディスプレイは SPI3 を使います。

## アンテナスイッチ (PI4IOE5V6408、P0)

Cap の RF スイッチは、内部 I²C バス上の PI4IOE5V6408 I/O エキスパンダ（アドレス `0x43`、400 kHz）のポート P0 で有効になります。起動時にファームウェアは次の処理を行います。

1. エキスパンダを初期化する。
2. P0 を出力に設定し、ハイインピーダンスモードを無効にして **High** にする。
3. 出力レジスタを読み戻す。

すべての手順が成功し、P0 が High と読み戻せた場合にのみ、Cap が**見つかった**とみなされます。そうでなければ、ステータスバーに `SEM CAP LoRa` と表示されます。それでもファームウェアは SX1262 の起動を試みますが、スイッチが有効でなければ有効な送受信はできません。Cap 内部の送信／受信の切り替えは SX1262 の DIO2 ピンで行われます（RadioLib のデフォルトで、M5Stack の公式サンプルと同じです）。

`M5Cardputer.begin()` は内部 I²C バスを立ち上げるため、無線の起動前に実行する必要があります。エキスパンダはこのバスをキーボードコントローラや IMU と共有しています。

## 無線の設定

| 設定 | 値 |
|---|---|
| TCXO | **3.0 V**、レギュレータは **LDO** モード（M5Stack の公式サンプルと同じ） |
| 過電流保護 | 140 mA |
| 受信ゲイン | ブースト（感度向上のため、Meshtastic と同じ） |
| モデム | LoRa、BW 250 kHz、SF 11、CR 4/5（Meshtastic LongFast） |
| 同期ワード | `0x2B`（Meshtastic） |
| プリアンブル | 16 シンボル |
| ヘッダー / CRC | 明示ヘッダー、ペイロード CRC オン |
| 送信出力 | 2–22 dBm、リージョンごとに制限（[frequencies.md](frequencies.md#送信出力)を参照） |
| 周波数 | リージョンから計算（[frequencies.md](frequencies.md) を参照） |

受信は DIO1 の割り込みで駆動されます。安全策として、ファームウェアはループのたびに DIO1 のレベルも確認し、受信も送信もないまま 10 分経つと受信を再設定します。送信はブロッキングで、フレームが送信し終わるまでメインループ、つまり UI は停止します（最大長のフレームで最大約 2.2 秒）。

## 共有バス

- **microSD スロットとの SPI。** 無線がバスを使っている間カードがバスを無視するよう、SD カードの CS（G12）は High に保たれます。v1 は実行時に SD カードを使いません。M5Launcher がファームウェアのインストール時に使うだけです。
- **キーボードとの I²C。** アンテナスイッチのエキスパンダは、TCA8418 キーボードコントローラと同じ内部 I²C バス上にあります。ファームウェアは起動時に一度だけエキスパンダに書き込みます。

## GNSS (v1 では未使用)

Cap には UART 接続の ATGM336H GNSS 受信機があります（ESP RX = G15、TX = G13、115200 baud）。v1 は UART を起動せず、位置情報も送信しません。位置の共有は[ロードマップ](roadmap.md)にあります。M5Stack によると LoRa の送信は GNSS 受信機に干渉するため、v2 ではこれを考慮する必要があります。

## アンテナと通信距離

Cap に付属のアンテナは **868 MHz** に調整されています。902–928 MHz のリージョンでも、わずかな損失で動作します。

- 919.875 MHz（ANZ）は調整周波数より約 6 %、903.875 MHz（BR_902）は約 4 % 高い周波数です。調整周波数から離れると、アンテナの VSWR が上がります。
- VSWR 2:1 では電力の約 11 % が反射され、損失は ≈ **0.5 dB** です。3:1 では ≈ **1.25 dB** です。
- このアンテナの 915 MHz での公開された測定結果はありません。損失は約 **0.5–2 dB**、通信距離にしておよそ 5–20 % と見込んでください。長距離でも使えますが、理想的ではありません。

通信距離に最も影響する要素（重要な順）:

1. **高さと見通し。** デバイスを数メートル高くしたり、窓際、ベランダ、屋上に移動したりするほうが、アンテナを替えるよりはるかに効果があります。建物、丘、人体は 900 MHz 帯の電波を遮ります。
2. **使用する帯域に合わせたアンテナ。** 902–928 MHz のリージョン（ANZ、BR_902、US、JP など）では、「広帯域」ではなく **915 MHz** に調整されたアンテナを購入してください。863–870 MHz のリージョン（EU_868、RU など）では、キット付属の 868 MHz アンテナが適しています。
3. **垂直に立てる**こと。他のノードと同じ偏波にします。
4. **許可された最大出力。** デフォルトの設定は 22 dBm です。リージョンによって実効出力が下がることがあります（JP では 13 dBm）。

キット付属の 868 MHz アンテナでは、BR_902 のほうが ANZ よりアンテナの調整周波数にわずかに近いのですが、ブラジルのコミュニティは ANZ を使っています。[frequencies.md](frequencies.md#帯域ごとのアンテナ) を参照してください。

**アンテナを取り付けずに送信しないでください。** 何も接続されていないコネクタに送信すると、電力がパワーアンプに反射して戻り、損傷するおそれがあります。

## M5Launcher でのインストール

リリースイメージは [`bin/`](../../bin/) にあります。

| ファイル | 用途 |
|---|---|
| `M5-Mesh-Hello.bin` | アプリケーションイメージ。SD カードから **M5Launcher** でインストールします。 |
| `M5-Mesh-Hello-merged.bin` | esptool や Web フラッシャーでオフセット `0x0` に書き込むフルフラッシュイメージ（ブートローダー + パーティションテーブル + boot_app0 + アプリ）。**M5Launcher とそれでインストールしたアプリを含め、フラッシュ上のすべてを置き換えます**。M5Launcher を使わない場合にのみ使用してください。 |
| `SHA256SUMS` | 両イメージの SHA-256 チェックサム |

手順:

1. ダウンロードしたファイルを検証します: `bin/` の中で `sha256sum -c SHA256SUMS`（Windows では `certutil -hashfile M5-Mesh-Hello.bin SHA256` を実行して比較）。[security.md](security.md#リリースの検証) を参照してください。
2. `M5-Mesh-Hello.bin` を microSD カードにコピーします。
3. M5Launcher で SD カードを選び、ファイルを選択してインストールします。
4. アンテナをねじ込んで取り付けてから、アプリを起動します。

パーティションに関する注意:

- M5Launcher は、インストールするバイナリのサイズに合わせたアプリケーションパーティションを作成します。v0.1.0 は約 590 KiB（603,744 バイト）です。ファームウェアは SPIFFS/LittleFS パーティションを使わず、保存するものはすべて **NVS**（名前空間 `meshhello`。[architecture.md](architecture.md#永続化-nvs) を参照）に入ります。
- 新しいバージョンをインストールするには、まず M5Launcher で**古いバージョンを削除**し（**PMan → Remove**）、それから新しいバイナリをインストールします。これでパーティションが解放され、新しいイメージに正しいサイズのパーティションが割り当てられます。
- 設定、鍵ペア、あいさつ済みの一覧、保存された相手は NVS にあり、通常はアプリを再インストールしても残ります。M5Launcher が NVS を消去するかどうかは、Launcher のバージョンと使用したオプションによります。

**M5Launcher がインストールされたデバイスで `pio test` を実行しないでください。** PlatformIO のデバイス上テストランナーは独自のイメージを書き込み、M5Launcher とそのアプリを上書きします。このプロジェクトのテストはすべて PC 上でネイティブに実行します（[development.md](development.md) を参照）。

## ディスプレイに関する注意

現在の M5GFX では、Cardputer-Adv の回転 0 がすでに横向き（240 × 135）です。ファームウェアが `setRotation(1)` を呼ぶことはありません。
