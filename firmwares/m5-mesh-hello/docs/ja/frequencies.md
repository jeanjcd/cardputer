# リージョンと周波数

M5-Mesh-Hello v0.1.0 の無線リージョン、周波数、送信出力、デューティサイクルについてのすべてです。値はすべて [`src/mesh/region.h`](../../src/mesh/region.h) と [`src/mesh/region.cpp`](../../src/mesh/region.cpp) から取っています。ネイティブテスト `test/test_docs_regions` が、CI の実行のたびに、この文書の**英語版**にあるリージョン表をコードと照合しています（[テーブルの正確さを保つしくみ](#テーブルの正確さを保つしくみ)を参照）。

> **法的な注意。** 必ず、実際にいる国のリージョンを使ってください。地域の電波規則（周波数、出力、デューティサイクル、アンテナ利得）を守る責任は利用者にあります。この文書は技術情報であり、法的助言ではありません。

> **日本でお使いの方へ。**
>
> - 日本のリージョンは **JP**（バンド 920.5 – 923.5 MHz、LongFast **923.375 MHz**）です。この周波数は Cap LoRa-1262 の M5Stack 定格（868–923 MHz）をわずかに超えるため、JP は**実験的**リージョンであり、性能は測定されていません。
> - JP の出力上限は、日本の規制に合わせてリージョン表で **13 dBm** に設定されています。Config で 22 dBm を設定していても、実効出力は 13 dBm です（画面表示 `22 dBm (efetiva 13)`）。
> - 日本国内で使用するには、**電波法**を守り、**技術基準適合証明等（技適）を受けた機器**を使う必要があります。**Cap LoRa-1262 の技適の有無は利用者ご自身で確認してください。** 本プロジェクトは、このモジュールが技適を取得していると主張するものではありません。
> - このファームウェアは、日本の 920 MHz 帯の技術基準（ARIB STD-T108 など。キャリアセンスや送信時間に関する要件を含みます）への適合について評価されておらず、キャリアセンス（LBT）も実装していません。
> - **法令の遵守は利用者の責任です。** 詳しくは[実験的リージョン](#実験的リージョン)を参照してください。

## Meshtastic のリージョンとは

LoRa 無線が一度に受信できるのは、ちょうど 1 つの周波数だけです。2 つの Meshtastic ノードが通信するには、同じ周波数と同じモデム設定を使う必要があります。Meshtastic は規制区域ごとに**リージョン**を定義しています。リージョンは、周波数帯（開始と終了）、デューティサイクルの上限、出力の上限、チャンネル間隔からなります。ノードはリージョン、チャンネル名（ここでは `LongFast`）、帯域幅から、固定の計算式で実際の中心周波数を計算します。そのため、同じリージョンでデフォルトのチャンネルを使うノードは、調整しなくても同じ周波数になります。

M5-Mesh-Hello は常に **LongFast** プリセット（帯域幅 250 kHz、拡散率 11、符号化率 4/5、同期ワード `0x2B`、プリアンブル 16 シンボル、明示ヘッダー、CRC オン）を、`LongFast` という名前のデフォルトのプライマリチャンネルで使います。選べる無線の設定はリージョンだけです。**Config** 画面（`Região`。Enter で一覧を順に切り替え）で変更します。デフォルトは **ANZ** です。

## 周波数の計算方法

コードは、単精度浮動小数点演算も含め、Meshtastic の `RadioInterface::applyModemConfig()` に正確に従っています（[`regionFreqMHz`](../../src/mesh/region.cpp)）。

```
hash        = djb2("LongFast")                       // 130429955
numChannels = floor((freqEnd - freqStart) / (spacing + bw/1000))
slot        = hash % numChannels
freq        = freqStart + bw/2000 + slot * bw/1000   // MHz; bw in kHz (250)
```

- `djb2` は古典的な文字列ハッシュです。`h = 5381` から始め、各バイトについて `h = h * 33 + byte` を符号なし 32 ビット値として計算します。`"LongFast"` では **130429955** になります。
- `bw/2000` は帯域幅の半分を MHz で表したもの（0.125 MHz）で、チャンネルの中心はスロットの開始から帯域幅の半分だけ上になります。
- `numChannels` が 0 になる場合（1 チャンネル分より狭いバンド）、コードは `freqStart + bw/2000` を返します。サポートされているリージョンでこれに該当するものはありません。

### 計算例: ANZ

| ステップ | 値 |
|---|---|
| バンド | 915.0 – 928.0 MHz、間隔 0 |
| `numChannels` | floor(13.0 / (0 + 0.25)) = **52** |
| `slot` | 130429955 mod 52 = **19** |
| `freq` | 915.0 + 0.125 + 19 × 0.25 = **919.875 MHz** |

他のリージョンも同じ方法で計算します。

| リージョン | numChannels | slot | LongFast (MHz) |
|---|---|---|---|
| BR_902 | 22 | 7 | 903.875 |
| US | 104 | 19 | 906.875 |
| EU_868 | 1 | 0 | 869.525 |
| SG_923 | 32 | 3 | 917.875 |

### チャンネルハッシュ

受信側が正しい鍵を選べるよう、すべてのフレームはヘッダーに 1 バイトのチャンネルハッシュを持っています。これは、チャンネル名の全バイトの XOR と、鍵の全バイトの XOR をさらに XOR したものです。`"LongFast"` とデフォルト鍵では **`0x08`** になります。[protocol.md](protocol.md#チャンネル暗号化-aes-128-ctr) を参照してください。

## 送信出力

Config 画面（`Potência`、デフォルト 22）で 2 から 22 dBm の出力を設定します。無線は**実効出力**を使います（[`effectiveTxPower`](../../src/mesh/region.cpp)）。

```
limit     = region power limit, or 17 dBm if the region's limit is 0 ("unknown", as in Meshtastic)
effective = min(user setting, limit, 22)     and at least 2 dBm
```

（`limit` はリージョンの出力上限で、上限が 0（Meshtastic と同様に「不明」）の場合は 17 dBm。`effective` は設定値、`limit`、22 の最小値で、最低 2 dBm です。）

22 dBm は SX1262 の最大値です。実効出力が設定値より低い場合、Config 画面には両方が表示されます。たとえば UA_868 や PH_868 では `22 dBm (efetiva 14)`（「実効 14」）、RU や SG_923 では `22 dBm (efetiva 20)`、JP では `22 dBm (efetiva 13)` です。出力の上限は、リージョンを変更するたびに適用し直されます。

アンテナ利得は考慮されません。地域の規則が EIRP/ERP を制限していて高利得アンテナを使う場合は、自分で出力を下げてください。

## デューティサイクルと送信時間の予算

一部のリージョンでは、デバイスが送信してよい時間の割合が制限されています。EU_868 と TH は 10 %、UA_868 は 1 % です。これらのリージョンでは、ファームウェアは直近 1 時間のローリング送信時間を記録し（[`AirtimeBudget`](../../src/mesh/region.h)）、次のフレームが予算を超える場合はフレームを保留します。

- **予算** = 1 時間のデューティ %: 10 % → **1 時間あたり 360 秒**、1 % → **1 時間あたり 36 秒**。
- **集計方法**: 1 分単位のバケットを 61 個使います。分 *M* の間に送信したフレームは分 *M + 60* まで数え続けられるので、**最低 3600 秒**（最大 3660 秒）カウントされます。これは安全側に倒した設計です。
- **各送信の前に**、ファームウェアはフレームの送信時間（ミリ秒単位に切り上げ）を計算し、`used + airtime ≤ budget` を確認します。条件を満たさない場合、そのフレームと後ろに並んでいるすべてのフレームは**待機**します。何も破棄されません。ステータスバーには赤で `duty limit` が表示され、Config 画面には `Ar 1h: Xs de Ys (duty Z%)`（「直近 1 時間の送信時間: Y 秒中 X 秒」）が表示されます。
- デューティサイクル 100 % のリージョンでは予算はなく、Config のこの行も表示されません。

### 送信時間

ファームウェアは Semtech SX126x の式（[`loraAirtimeUs`](../../src/mesh/region.cpp)）を LongFast の設定で使います: SF11、BW 250 kHz、CR 4/5、プリアンブル 16、明示ヘッダー、CRC オン、低データレート最適化オフ。

```
Tsym          = 2^SF / BW                              = 2048 / 250 kHz = 8.192 ms
preamble      = (16 + 4.25) × Tsym                     = 165.888 ms
payloadSymbols = 8 + ceil((8·L − 4·SF + 28 + 16) / (4·SF)) × CR   // L = whole frame length in bytes, CR = 5
               = 8 + ceil(8·L / 44) × 5
airtime       = preamble + payloadSymbols × Tsym
```

（`L` はフレーム全体の長さ（バイト）、`CR` = 5 です。）

つまり、どのフレームにも固定で **≈ 231 ms**（L = 0）かかり、さらに 5.5 バイトごとに 5 シンボル（41 ms）が加わります。平均すると **1 バイトあたり ≈ 7.4 ms** です。

| フレーム長 L（ヘッダー + ペイロード） | 送信時間 |
|---|---|
| 0 B（理論上の最小値） | 231 ms |
| 22 B（短い公開テキスト、たとえば「hi」） | 395 ms |
| 88 B（デフォルト名での自分の NodeInfo） | 887 ms |
| 128 B | 1.21 s |
| 200 B | 1.75 s |
| 255 B（最大フレーム） | 2.16 s |

典型的なフレームは約 **1 秒**です。EU_868 では 1 時間あたり 360 秒で、NodeInfo サイズのフレームなら 1 時間におよそ 400 個に相当し、このファームウェアが通常使用で送信する量よりはるかに多くなります。UA_868（1 時間あたり 36 秒）では、そのようなフレームが 1 時間に約 40 個収まります。

## 実験的リージョン

M5Stack Cap LoRa-1262 の定格は **868–923 MHz** です。SX1262 チップ自体は **150–960 MHz** に合わせられるので、無線は Cap の定格からわずかに外れた周波数にも設定できます。ただし RF スイッチ、フィルタ、整合回路は定格帯域向けに設計されています。帯域外では送信出力が弱くなり、感度も悪くなると考えてください。どの程度悪くなるかは測定されていません。

ファームウェアには、LongFast の周波数が [860, 868) MHz（IN、NZ_865、NP_865、KZ_863）または (923, 925] MHz（JP、TW、TH）にあるリージョンが含まれており、それらには印が付きます。

- Config では、リージョンに `(exp)` が付きます。例: `IN 865.875 (exp)`
- 選択すると、トースト `Fora da faixa do Cap (exp)`（「Cap の帯域外（実験的）」）が表示されます。
- 選択中は、Config に `! Fora de 868-923 MHz do Cap (exp)`（「Cap の 868–923 MHz の範囲外」）と表示されます。

実験的リージョンは、それがお住まいの国の正しいリージョンである場合にのみ使用し、通信距離は短くなると考えてください。

**日本（JP）について。** JP の LongFast 周波数 923.375 MHz は、Cap の定格上限 923 MHz をわずか 0.375 MHz 上回ります（Config の表示は `JP 923.375 (exp)`）。JP の出力はリージョン表で 13 dBm に制限されます。日本の 920 MHz 帯は ARIB STD-T108 などの技術基準で規定されており、キャリアセンスや送信時間に関する要件があります。このファームウェアはそれらへの適合について評価されておらず、キャリアセンス（LBT）も実装していません。日本で使用する前に、電波法と技適（技術基準適合証明等）の要件を確認し、**Cap LoRa-1262 の技適の有無をご自身で確かめてください**。本プロジェクトはこのモジュールが技適を取得しているとは主張しません。法令の遵守は利用者の責任です。

## ブラジル

ブラジルで関係するリージョンは 2 つあり、互いに受信**できません**。

| リージョン | LongFast | 状況 |
|---|---|---|
| **ANZ** | 919.875 MHz | 現在ブラジルの Meshtastic コミュニティが使っているリージョン（たとえば [meshbrasil.com](https://meshbrasil.com)）。**このファームウェアのデフォルト。** |
| **BR_902** | 903.875 MHz | Meshtastic のブラジル向け公式リージョン（902–907.5 MHz）。 |

Anatel（ブラジル国家電気通信庁）の制限放射（免許不要）機器に関する規則では、902–928 MHz 帯のうち **902–907.5 MHz と 915–928 MHz** で LoRa のようなスペクトラム拡散機器が認められています。907.5–915 MHz の区間は含まれません。上の 2 つのスロットはどちらも許可された区間に入っています。これを前提にする前に、最新の Anatel の規則を確認してください。

ANZ で誰も見えない場合は、地元のユーザーにどのリージョンを使っているか聞くか、BR_902 を試してください。

## 帯域ごとのアンテナ

アンテナは特定の周波数範囲に合わせて調整されています。そこから離れると VSWR が上がり、電力の一部が放射されずに反射されます。

| リージョンの周波数 | 最適なアンテナ |
|---|---|
| 863–870 MHz（EU_868、RU、UA_868、PH_868、IN、NZ_865、NP_865、KZ_863） | 868 MHz アンテナ |
| 902–928 MHz（ANZ、BR_902、US、KR、MY_919、SG_923、PH_915、JP、TW、TH） | 915 MHz アンテナ |

Cap に付属のアンテナは 868 MHz に調整されています。902–928 MHz のリージョンでも動作し、損失は約 **0.5–2 dB** と見込まれます。919.875 MHz は調整周波数より約 6 %、903.875 MHz は約 4 % 高い周波数です。VSWR 2:1 では電力の約 11 % が反射されます（≈ 0.5 dB）。3:1 では損失は ≈ 1.25 dB です。これは通信距離にしておよそ 5–20 % の損失になります。902–928 MHz のリージョン用にアンテナを購入する場合は、「広帯域」ではなく 915 MHz に調整されたものを選んでください。868 MHz アンテナでは、BR_902（903.875 MHz）のほうが ANZ より調整周波数に少し近くなります。通信距離に関するその他のアドバイスは [hardware.md](hardware.md#アンテナと通信距離) を参照してください。

**アンテナを取り付けずに送信しないでください。** ファームウェアは起動直後に NodeInfo を送信します。

## テーブルの正確さを保つしくみ

この文書の英語版 [`docs/en/frequencies.md`](../en/frequencies.md) では、リージョン表が HTML コメント `<!-- regions:begin -->` と `<!-- regions:end -->` の間に置かれています。ネイティブテスト [`test/test_docs_regions`](../../test/test_docs_regions/test_main.cpp) はそのファイルを読み、表の各行を解析して、同じ順序で `regionAt(i)` と照合します。照合するのは名前、バンドの端、`regionFreqMHz` で計算した LongFast の周波数、出力の上限、デューティサイクル、実験的フラグです。このテストは `pio test -e native` のたびに実行されるので、すべての push とプルリクエストで CI でも実行されます。`region.cpp` を変更する場合は、同じコミットで英語版の表を更新し（列の順序はテストにとって重要です）、その後で翻訳を更新してください。翻訳はこのテストでは検証されません。
